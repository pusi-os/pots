    План: Кенни, язык интерфейса, вылет Инструментов, Ollama-скрипты, STT/TTS + Piper

    Дата: 2026-10-28 · Статус: выполнено, сборки и публикация — в §9

    Скоуп согласован с пользователем: - Кенни: круг капюшона дорисовать впереди перед глазами (как у настоящего персонажа); образ «Полосатый» удалить целиком (Гермес остаётся, про него отдельной задачи нет). - LiteRT на десктопе считается рабочим; нужно только убрать вылет раздела «Инструменты» и вернуть провайдера локальных моделей в «Сервисы», а там, где движок недоступен, — показывать секции неактивными с сообщением. - Ollama подключается как openai-compatible endpoint (http://localhost:11434/v1); никаких масштабных изменений в приложении — только вспомогательные скрипты для установки/скачивания моделей. - Desktop Tools: когда локального LiteRT-движка нет (нет AVX2), использовать Ollama как embedding-бэкенд: скачивать в Ollama embedding-модель (embeddinggemma, аналог мобильной embeddinggemma-2-text-vision-440m) через настроенный в «Сервисах» OpenAI-Compatible endpoint и считать векторы через Ollama API (/api/embed), а не через LiteRT. - Desktop-окно: UI должен корректно перестраиваться при изменении размера окна — рабочая область больше/меньше, элементы перемещаются за границами; проверить, что Canvas и адаптивные колонки следуют за размером окна (старый Pots.desktop указывал на ProGuard-билд; теперь run-pots-desktop.sh указывает на dev-сборку). - Prosvetim: добавить провайдером (тот же endpoint, что у Trial Smart https://omni.prosvetim.ru/v1, но со своим ключом пользователя и выбором моделей из API). - Убрать дублирующую кнопку «Наш Telegram-канал» в «Настройки → Сервисы» (остаётся только кнопка-ссылка выше). - Переключатель языка интерфейса в «Настройки → Общие» перед секцией темы. - В конце: секция STT/TTS в «Общих» + встроенный движок Piper (см. §5).

    1. Кенни (PARKA) + удаление «Полосатого»

    Проблемы (подтверждены рендером Paparazzi, screenshotTests/.../PotsikDebugTest.kt): - Щель-«окно» капюшона задана в сырых пикселях hh+2..hh+12 без S(), поэтому на любом масштабе кроме 1.0 она не совпадает с глазами: глаза полностью скрыты. - Из-за дробного hh (bob) строки у границы окна «перещёлкиваются» между «в окне/не в окне» — мерцание каймы. - Очки рисуются на лице и выглядывают из щели — для капюшона должны быть выключены всегда.

    Решение: - PotsikCostumes.drawParka(): границы окна в целых строках относительно oy, т.е. dy2 ∈ [-S(3) .. S(7)] (окно = юниты 5..15: кайма глаз видима, рот и нос скрыты), ширина S(14); кайма-линии на тех же целых строках. Мерцание исчезает, т.к. условие стало чисто целочисленным. - Круг капюшона впереди: эллиптическое кольцо (мех + чернила с обеих сторон) вокруг проёма лица — как у настоящего персонажа, лицо сидит глубоко в капюшоне. - PotsikBody: для PARKA не рисуем нос (в окне только глаза) и всегда трактуем glassesOn = false. - «Потсики» в настройках: при Кенни переключатель очков неактивен с пояснением. - Проверка: рендеры в двух масштабах, обновление золотых образов. - «Полосатый» (STRIPES) удалён целиком: enum в PotsikModel, drawStripedCap() в PotsikCostumes, drawPrisonStripes() + ankleCuff() + мёртвые sqDist()/ distToSegment() в PotsikBody, таблица костюмов в docs/features/potsiki.md (18 → 17); бантер KENNY оставлен (упоминание имени, не образ).

    2. Вылет «Инструментов» и провайдер локальных моделей

    Первопричина (найдена): в рабочем дереве (незакоммичено) из AppModule.kt удалена регистрация single<LocalInferenceEngine?> { createLocalInferenceEngine() }, а RemoteDataRepository переведён на getOrNull(). Из-за этого: - koinInject<LocalInferenceEngine>() в ToolsSettings.VectorStorageSection падает NoDefinitionException → вылет при открытии «Инструментов»; - isLocalInferenceAvailable() всегда false → провайдер «Local Model» исчезает из «Сервисов» на всех платформах.

    Решение (минимальное): - Вернуть регистрацию в AppModule и get() в RemoteDataRepository. - ToolsSettings: koinInject<LocalInferenceEngine?>(); при null секция векторного поиска рендерится неактивной с текстом «инструмент не поддерживается на этом компьютере». - «Сервисы»: он-девайс сервис больше не прячется из списка добавления/настроек — карточка рендерится неактивной с тем же сообщением, когда движка нет.

    3. Язык интерфейса

    • AppLanguage { SYSTEM, ENGLISH, RUSSIAN } в AppSettings (ключ + StateFlow).
    • Корень приложения: CompositionLocalProvider(LocalComposeEnvironment provides …) (CMP 1.12: официальный способ переопределить локаль ресурсов) + key(language) для полной рекомпозиции.
    • Все точки, читающие Locale.current.language (бантер Потсика, подписи образов, пресеты характера, имена фонов), читают переопределение.
    • «Настройки → Общие»: карточка «Язык интерфейса» перед секцией темы; варианты: Системный (по умолчанию) / Русский / English.

    4. Ollama через openai-compatible

    Приложение уже умеет: OpenAICompatible с базой по умолчанию http://localhost:11434/v1 — список моделей /v1/models, чат /v1/chat/completions, инструменты работают. Добавляем только скрипты:

    • scripts/ollama-setup.sh — детект установки/запуска, установка с официального релиза под ОС/архитектуру (Linux tar.zst в ~/.local, macOS ollama-darwin.tgz, Windows — по инструкции), старт ollama serve, проверка /api/version.
    • scripts/ollama-models.sh — list (что стоит), pull <модель> с прогрессом, recommended (короткий список актуальных небольших моделей), подсказка какие id вписать в openai-compatible в настройках.

    5. STT/TTS: секция в «Общих» + движок Piper (после пп. 1–4)

    Задача (дописана по просьбе пользователя; расширена после регрессии голоса): - Сбивка голоса/языка: приложение не выставляло голос явно — движок говорил голосом системной локали, а не языка приложения (русский текст читался английским голосом). Исправлено: App.kt при каждом изменении языка/голоса/ скорости/тона выбирает голос под язык приложения (сохранённый → по языку → дефолтный движка) и применяет rate/pitch. - Секция «Озвучивание» в «Настройки → Общие»: - выбор движка: Нативный (системный, по умолчанию — как было), Piper (офлайн, встроенный), Облачный (заглушка: через inference-эндпоинт, позже); - для нативного — выбор системного голоса (Android: список голосов TTS; desktop/iOS/Web: авто-режим) + слайдеры скорости и высоты; - для Piper — выбор языка, затем голосов, загрузка модели с прогресс-баром и докачкой, персистентное хранение (~/.pots/piper/); - для облачного — список доступных моделей/голосов/языков (когда появится). - Настройки: TtsEngine { NATIVE, PIPER, CLOUD } в AppSettings (ключи tts_engine, tts_system_voice, tts_piper_voice, tts_rate, tts_pitch) + DataRepository/SettingsViewModel/SettingsUiState/SettingsActions. - Desktop: Piper ставится туда же (~/.pots/piper/), faster-whisper — для распознавания; та же секция в «Общих», те же ключи настроек. - Лучшие практики: докачка через HTTP Range, проверка размера/чек-суммы, загрузка в temp + атомарная замена, запуск бинарника как child process (никакого root), выбор голоса по языку интерфейса пользователя.

    Критерии приёмки: переключение движка сразу влияет на озвучку чата; обрыв загрузки продолжается с места остановки; выбранный голос переживает перезапуск.

    6. Провайдер Prosvetim + уборка дубля Telegram-кнопки

    • Новый провайдер Prosvetim (prosvetim): тот же endpoint, что у Trial Smart (https://omni.prosvetim.ru/v1/chat|models), но requiresApiKey = true — пользователь вводит свой ключ и выбирает модели из своего аккаунта через обычный /v1/models. Иконка ic_service_prosvetim.xml, referral-инструкция и расширенная сортировка моделей в ServicesSettings, каталог в docs/features/multi-service.md, тесты ServiceCatalogTest.
    • Убран дублирующий TextButton «Наш Telegram-канал» в «Настройки → Сервисы» (осталась кнопка-ссылка settings_telegram_nerosekta); неиспользуемый импорт и строки settings_telegram_channel (EN/RU) удалены.

    7. Desktop-окно: корректный ресайз

    • main.kt: минимальный размер окна 640×480; начальный размер 1280×800 — только стартовый. Весь контент (ChatScreen, SettingsScreen, PotsikOverlay, AnimatedBackdrop, StaggeredSettingsColumns) уже построен на fillMaxSize/BoxWithConstraints и следует за живым размером окна; Canvas Потсика пересчитывает area через onGloballyPositioned на каждую смену размера. Отдельного «кусочного» канваса в коде нет — симптом соответствовал старому бинарю из ProGuard-сборки, на который указывал Pots.desktop.

    8. Desktop Tools через Ollama embeddings

    • OllamaVectorizationManager.desktop.kt: когда createLocalInferenceEngine() вернул null (нет AVX2), десктоп использует Ollama вместо LiteRT: POST {ollama}/api/embed (nomic-embed-text, аналог мобильной embeddinggemma), фото из ~/Pictures, документы из ~/Documents, стор ~/.pots/vector_store_ollama.json со схемой/моделью/размерностью.
    • ToolsSettings: на десктопе карточка показывает Ollama-инструкцию и кнопку «Проверить Ollama» вместо скачивания LiteRT-модели; scripts/ollama-models.sh рекомендует nomic-embed-text.
    • docs/features/vector-search.md обновлён; Last verified — 2026-10-28.

    Задача (дописана по просьбе пользователя): - Секция «Озвучивание (TTS/STT)» в «Настройки → Общие»: - выбор движка: системный (по умолчанию, как сейчас) и Piper; - для системного — выбор голоса из доступных системе; - для Piper — выбор языка, затем голоса (все доступные для языка), загрузка модели с прогресс-баром и докачкой при обрыве, персистентное хранение. - Piper встроен в приложение: при выборе движка автоматически скачивается и разворачивается среда Piper (бинарник + espeak-ng-data по ОС), модель голоса (*.onnx + *.onnx.json с HuggingFace rhasspy/piper-voices) качается в хранилище приложения и используется для TTS в чате и всюду, где нужен голос. - Лучшие практики: докачка через HTTP Range, проверка размера/чек-суммы, загрузка в temp + атомарная замена, запуск бинарника как child process (никакого root), кэш моделей в ~/.pots/piper/, выбор голоса по языку интерфейса пользователя.

    Дизайн (кратко): - TtsEngineId { SYSTEM, PIPER } + настройки в AppSettings (движок, голос Piper, голос системный). - Desktop: PiperVoiceManager (скачивание/распаковка/реестр голосов) + PiperTtsInstance : TextToSpeechInstance (генерация wav через процесс piper, воспроизведение через javax.sound). Мобильные остаются на системном движке. - Каталог голосов: voices.json из релиза Piper (имя, язык, качество, размер, URL) — группировка по языку, показ всех доступных.

    Критерии приёмки: переключение движка сразу влияет на озвучку чата; обрыв загрузки продолжается с места остановки; выбранный голос переживает перезапуск.

    9. Сборки и публикация

    Порядок CI: spotlessApply → updateScreenshots → desktopTest. Релиз APK: ./gradlew :assembleFossRelease (setsid, ~4 мин) → scripts/publish-apk.sh --no-bump --no-commit → 222 (manifest.json, pots-latest.apk), бамп версии, push origin/main.
