    Потсики: the costumes, the movements and the position

    Plan date: 2026-10-25

    Потсик is the PotSquad firmware's character, ported into the app. This plan covers the second pass over that port: the costume list is cut down to the eighteen the product wants, each of them is checked against the firmware shape for shape, the character's movements are given the timing they need to be watchable, and the place he stands in is remembered the way the settings say it is.

    The reference is the firmware itself — firmwares/PotSquad/src/potsy.cpp (9 395 lines), with src/shambler.inc, src/th3_0n3.inc and Theme::drawWing() from src/theme.cpp. Everything below is measured against that file, not against the app's own current drawing.

    1. The costume list

    2. What has to change in the code

    2.1 The costumes themselves

    • PotsikOutfit loses WOLFPELT and SHARK and carries the new names.
    • wearsBaseClothes loses WOLFPELT: the tee and the shorts stay on under NONE, TINFOIL and CHROMEWING only.
    • PotsikCostumes.kt loses drawWolfPelt(), drawShark() and peltOn().
    • PotsikBody.kt loses the wolf cape, the pelt skulls, the shark hood and the shark fins, and every branch that mentions the two removed costumes.
    • The screenshot test's outfit grid loses two rows.

    2.3 The closed eyes

    The firmware draws the sleeping lids in furLight, which on the default yellow fur is the same colour as the face — so the eyes vanish entirely when he is asleep or waking up. In the app the lids are drawn in a dark line instead, so a shut eye still reads as a shut eye on the face.

    2.4 The working tile

    ToolMessage.kt draws the working tile with a surfaceVariant background, which puts a rectangle behind the character while a request runs. The tile keeps its place — it is the character's slot, and the caption under it is measured against it — but the rectangle goes: the background becomes transparent, so the character stands on the chat rather than on a card.

    The same tile is used by the main chat and by the interactive (pots-ui) chat, so both lose the rectangle at once.

    2.5 The timings of the animations played during a request

    The playlist that plays while a request runs gives each animation a slot, and the animation has to fill the slot: it must not be cut off half way through, and it must not hold for so long that it becomes a still picture.

    • One slot is 6 seconds at the normal tempo.
    • The tempo still scales it, but the slot never falls below 4 seconds and never rises above 12 seconds.
    • The mood and the pose both last the whole slot. Today they last the unscaled 3.2 seconds while the slot is the scaled one, so at the default 70 % tempo every animation is cut a third of the way through.
    • The tool's own pose, the one that says what the agent is doing, holds for at least 4 seconds before the playlist takes over.

    2.6 Where he stands

    Problem Fix
    The position is never written to disk pinnedX/pinnedY get their own settings keys
    sizePercent, tempoPercent, the banter switch, the drag switch and the placement mode are all dropped on every save Each of them gets its own key
    The size slider works backwards — raising it makes him smaller One size model: the drawn size and the bounds are computed from the same number
    sizePercent is not in the bounds, so a 150 % Потсик hangs off the screen The bounds use the same effective size the drawing uses
    The default placement mode contradicts its own documentation Session is the default, as the documentation says
    A move in the session mode is written to disk, so "session" is really "for ever" Only the persistent mode writes the position down; the session mode keeps it in memory
    The agent's move reports success in the system mode, where nothing moves The tool says the move was refused
    Switching to the persistent mode loses the spot he is standing in The mode switch seeds the stored position from where he is

    4. What "done" means

    • The eighteen costumes are the only ones in the list, with the names above.
    • Each of them is drawn the way the firmware draws it, with its own animations running.
    • A shut eye is still a shut eye, not a blank face.
    • There is no rectangle behind the character while a request runs.
    • Every animation of the working playlist plays its whole cycle.
    • He can be dragged, moved by the agent, and his place is remembered as the placement mode says.
    • He is on screen in every section.
    • The unit tests pass, the format is clean, the APK builds, every costume is checked in the emulator, and the APK is on the dashboard.
