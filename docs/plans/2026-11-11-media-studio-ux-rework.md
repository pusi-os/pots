## Диагностика (уже выполнена)

### Логи телефона

Приложение в release-сборке **не пишет ничего** по медиа-операциям
(`grep` по logcat: только системные теги; в медиа-слое нет ни одного
`println`/логгера — проверено). Буфер не содержит следов генераций.
Вывод: без добавления логирования причину «не создаётся» дистанционно не
подтвердить; P0 добавляет логирование и видимые ошибки.

Гипотезы отказа «с нуля» (по убыванию вероятности):

1. **Ключ**: `AppModule.kt:201-207` и `AgentToolSet.kt:67-105` берут
   `getConfiguredServiceInstances().firstOrNull()`. После переустановки
   (данные стёрты) первый инстанс может быть без ключа → `401` → тихая
   красная строка, которую легко не заметить.
2. **Модель не выбрана** → сообщение «Выбери модель… в настройках сервисов»
   мелким красным текстом (легко пропустить).
3. `Параметры` чипов берутся из `models.firstOrNull()`
   (`MediaStudioScreenFull.kt:321`), а не из выбранной модели — неизвестные
   opts провайдер молча игнорирует; в `strict` был бы 422.
4. Кнопка «Создать» при пустом промпте молча делает `return` — без подсказки.

### Отказ агента с фото

Это **отсутствие функциональности**, а не сбой:

- `generate_image` принимает только `image_url` — публичный `https`
  (`MediaTools.kt:93`). Фото из чата — локальный файл, агенту нечего передать.
- `list_media_models` не отдаёт `acceptsImageReference` — агент не может
  выбрать модель, умеющую редактировать по фото.
- Студийный пайп референсов шлёт несуществующий ключ `input_urls`
  (`MediaStudioViewModel.kt:99`) — неизвестные параметры игнорируются,
  референс молча выбрасывается. Для локальных файлов контракт требует
  `*_base64` (`data:<mime>;base64,…`) или Files API (см.
  `docs/knowledge/media-providers/plusvibe.md`, раздел «Свои файлы»).

## Дизайн-спека (пункты 1 и 5)

Общий стиль: тёмный «холст» с точечной сеткой, стеклянные панели
(`surface` с альфой + `tonalElevation`), скругления 12-16.dp, акцент —
`primary`. Все действия — иконки без подписей (доступность:
`contentDescription` на русском). `material-icons-extended` уже в
зависимостях (`composeApp/build.gradle.kts:96`); есть и свои
`composeResources/drawable/ic_*.xml`. Базовый компонент —
`SmallIconButton` (`ui/chat/composables/SmallIconButton.kt`), 36.dp круг.

### Верхняя панель студии (иконки слева направо)

| Действие | Иконка | Куда ведёт |
|---|---|---|
| Чат (выход) | `Icons.AutoMirrored.Filled.Chat` | `onExit` |
| Медиа (домой студии) | `Icons.Filled.AutoAwesome` | сброс/центр канваса |
| Импорт | `Icons.Filled.AddPhotoAlternate` | file picker (есть) |
| Модели | `Icons.Filled.Tune` | bottom-sheet выбора модели |

Панель — компактный `Row` из `SmallIconButton` в стеклянной капсуле,
прижата к верху канваса (оверлей), не занимает отдельную строку.

### Нижняя панель (над системным краем)

| Действие | Иконка | Примечание |
|---|---|---|
| Озвучка вкл/выкл | `VolumeUp`/`VolumeOff` | переключатель, состояние из `speechEnabled` |
| Голосовой ввод | `Mic` | HandsFree-распознаватель, где доступен |
| Спросить агента | `Icons.AutoMirrored.Filled.Send` | шлёт промпт через `onAskAgent` |
| Режим (изображение/видео) | `Image`/`Movie` | сегмент-переключатель |
| **Создать** | крупная круглая `primary`-кнопка `Sparkles`/`ArrowForward` | единственный текстовый акцент не нужен |

Поле промпта — одно, в нижней панели, `maxLines=3`. Второго поля нет.

### Канвас

- Фон: `surface` → тонкая точечная сетка (рисуется в `Canvas`, шаг 24.dp,
  точки `onSurfaceVariant` с альфой ~0.15), пан/зум как сейчас.
- Элементы: скругление 12.dp, тень (2-6.dp), у выбранного — рамка `primary`
  2.dp + угловые маркеры (drag для resize — на десктопе; на тач — пинч
  через `transformable`, уже есть).
- Прогресс генерации: на месте будущего элемента — карточка-скелетон
  (шиммер + имя модели + таймер), не одинокий спиннер по центру.
- Контекстное меню: скруглённая стеклянная `Surface` под точкой тапа,
  строки «иконка + подпись», координаты = `element + canvasOffset`
  (исправить баг). Действия: Вперёд/Назад (`FlipToFront`/`FlipToBack`),
  Дублировать (`ContentCopy`), Референс (`Link`/`Bookmark`), В галерею
  (`SaveAlt`), Удалить (`Delete`, красный), Закрыть.
- Пустое состояние: крупная иконка + 2 строки подсказки + стрелка на
  нижнюю панель.

### Выбор моделей

- Не `LazyColumn 96.dp`, а bottom-sheet (`ModalBottomSheet`): секции
  «Изображения»/«Видео», строка = имя + цена-бейдж (`secondaryContainer`)
  + отметка выбора; выбранная строка: фон `primaryContainer`, текст
  `onPrimaryContainer` (исправление цвета), справа `Check`.
- В студии текущая модель показана чипом рядом с кнопкой «Создать»
  (тап — тот же sheet).
- `MediaModelsSettings.kt`: те же цвета (`onPrimaryContainer`), бейджи цен.

### Параметры генерации

`FilterChip` с `selected` (сейчас `AssistChip` без подсветки), параметры
брать у **выбранной** модели; неизвестные ключи не отправлять.

### Ошибки

Не красная строка, а `Snackbar` + иконка; текст на русском, с действием
(«Повторить», «Открыть настройки»), если причина — ключ/модель. Ошибка
полностью логируется (см. логирование).

## Фазы

### P0 — корректность (до любых перерисовок)

1. **Логирование медиа-слоя.** Минимальный `expect`-механизм: в
   `commonMain` объект `MediaLog { fun d/i/e(tag, msg, throwable?) }`,
   `actual` через `android.util.Log` (androidMain), `println` с тегом
   (остальные). Точки: загрузка каталога (число моделей), каждая подача
   (модель, размер тела, наличие референсов), каждый ответ опроса
   (статус, цена), каждая ошибка (полный стек). Файлы: новый
   `media/MediaLog.kt` + `expect/actual` по образцу `Platform.*`;
   вызовы в `PlusVibeMediaProvider`, `MediaGenerationRepository`,
   `MediaStudioViewModel`, `MediaTools`.
2. **Видимые ошибки.** `MediaStudioViewModel.error` → `Snackbar` в студии
   (хост: `MediaStudioScreenFull` получает `SnackbarHostState`), тексты
   на русском из `MediaException` (`mapError` уже маппит коды).
   Для `InvalidKey` — действие «Открыть настройки сервисов».
3. **Убрать второе поле ввода.** `ChatScreen.kt:1456`:
   `if (!isSandboxOpen)` → `if (!isSandboxOpen && !isMediaOpen)`.
4. **Надёжность «с нуля».** В `generateImage/generateVideo`: если модель
   в настройках пуста — автоматически брать первую доступную из каталога
   и сохранять (сейчас только фолбэк в памяти); пустой промпт —
   подсветить поле и подсказку, не тихий `return`. В `AppModule`/
   `AgentToolSet` для ключа брать **активный инстанс чата**, а не
   `firstOrNull()` (проверить, как его отдаёт `AppSettings`/`ChatViewModel`,
   например выбранный сервис в `uiState`).
5. **Баги канваса.** `menuOffset` += `canvasOffset`; убрать заглушку
   «Сохранить набор» (или реализовать: сериализовать список референсов в
   JSON и сохранить); `ParamChips` — параметры выбранной модели.
6. Удалить мёртвый `MediaStudioScreen.kt`; починить `docs/features/media-studio.md`
   (Key Files, поведение референсов, пункт про вход в студию).

### P1 — референсы (пункты 2 и 3)

1. **Модель данных.** `MediaModels.kt`: `data class MediaReference(val url:
   String? = null, val base64DataUri: String? = null, val localPath:
   String? = null, val isVideo: Boolean = false)`; поле
   `references: List<MediaReference>` в `MediaJobRequest`.
2. **Провайдер.** `PlusVibeMediaProvider.buildGenerateBody`: для каждой
   ссылки подобрать ключ по каталожным `params` выбранной модели
   (пересечение с `IMAGE_REFERENCE_KEYS`/`VIDEO_REFERENCE_KEYS`):
   `image_url`/`reference_image_urls` для публичных https, парные
   `*_base64` (полный `data:<mime>;base64,…`) для локальных байтов.
   Если модель не принимает вход — ошибка
   `MediaException.BadRequest("Модель … не принимает референс")` до отправки.
   Размер: локальный файл > 8 МБ — сначала `POST /v1/files` (дописать в
   провайдер) и использовать `*_file_id` (контракт в `plusvibe.md`).
3. **Студия.** Полоска референсов над нижней панелью: миниатюры 40.dp с
   крестиком удаления; источники — (а) «Как референс» из меню элемента
   (уже есть, направить в новый тип), (б) кнопка «+» в полоске —
   файловый пикер (тот же `rememberFilePickerLauncher`), (в) перетаскивание
   элемента. При генерации `ViewModel` кладёт набор в
   `MediaJobRequest.references` (удалить `input_urls`).
4. **Инструменты агента.** `MediaTools.generateImageTool`:
   - параметр `reference_image` (путь вложения/канваса или публичный
     https); локальный путь → читать байты (`readAppStorageBytes`/
     `PlatformFile`) → base64 data-URI;
   - авто-выбор модели с `acceptsImageReference`, если передан референс,
     а выбранная модель его не принимает (брать из каталога);
   - `list_media_models`: добавить `acceptsImageReference`,
     `acceptsVideoReference` в выдачу.
5. **Системный промпт агента**: в медиа-раздел добавить, что агент умеет
   генерировать/редактировать изображения и видео по приложенному фото
   через `generate_image(reference_image=…)`, и должен использовать
   вложение пользователя, когда просят «улучшить фото», «сделать меня
   где-то». (Раздел про инструменты в `docs/features/system-prompts.md`
   и соответствующий рантайм-файл — найти по `tools.md`/`AgentToolSet`.)

## Definition of done

- Изображение «с нуля» создаётся и с ключом, и с внятной ошибкой без него;
  каждая ошибка видна и залогирована.
- Фото-референс работает: студия (полоска) и агент (вложение чата),
  сценарий «я возле фонтана в Дубае» даёт изображение.
- В медиа-режиме одно поле ввода.
- Студия соответствует дизайн-спеке: иконки без текста, канвас с сеткой/
  рамками/шиммером, sheet моделей с корректными цветами выбора.
- Вход в студию доступен при непустом чате.
- Тесты/формат/скриншоты зелёные; сборка ставится на телефон поверх
  текущей (одна подпись).
