    Media Studio: UX/UI rework, references, diagnostics — 2026-11-11

    Статус: план готов к исполнению. Сессия переключается на модель со зрением; начинать с фазы P0 по порядку. Все пути — от корня apps/pots.

    Телефон для проверки: Nothing Phone A142 (Pacman), Android 16 (SDK 36), arm64-v8a. Беспроводной adb сопряжён: adb connect 192.168.1.210:44055. На телефоне уже стоит com.pusios.pots 3.11.3 (200), подписанный FOSS-ключом, в профиле пользователя 0. Ставить новые сборки можно поверх (подпись одна).

    Запрос пользователя (5 пунктов)

    1. Изучить и улучшить UX/UI раздела медиа; исправить цвета текста и выбора моделей.
    2. Проверить логи на телефоне: не создаётся изображение «с нуля»; агент отказывается улучшать фото пользователя и делать его «возле фонтана в Дубае».
    3. Добавить референс для генерации изображения.
    4. Убрать второе поле ввода внизу (которое отправляет в чат, а не на генерацию), когда включён режим медиа.
    5. Полнофункциональный современный канвас в трендовом дизайне; все кнопки (сверху: Чат, Медиа, Импорт, Модели; снизу: озвучка, спросить агента) — небольшие стилизованные векторные кнопки без текста, компактно и гармонично.

    Диагностика (уже выполнена)

    Логи телефона

    Приложение в release-сборке не пишет ничего по медиа-операциям (grep по logcat: только системные теги; в медиа-слое нет ни одного println/логгера — проверено). Буфер не содержит следов генераций. Вывод: без добавления логирования причину «не создаётся» дистанционно не подтвердить; P0 добавляет логирование и видимые ошибки.

    Гипотезы отказа «с нуля» (по убыванию вероятности):

    1. Ключ: AppModule.kt:201-207 и AgentToolSet.kt:67-105 берут getConfiguredServiceInstances().firstOrNull(). После переустановки (данные стёрты) первый инстанс может быть без ключа → 401 → тихая красная строка, которую легко не заметить.
    2. Модель не выбрана → сообщение «Выбери модель… в настройках сервисов» мелким красным текстом (легко пропустить).
    3. Параметры чипов берутся из models.firstOrNull() (MediaStudioScreenFull.kt:321), а не из выбранной модели — неизвестные opts провайдер молча игнорирует; в strict был бы 422.
    4. Кнопка «Создать» при пустом промпте молча делает return — без подсказки.

    Отказ агента с фото

    Это отсутствие функциональности, а не сбой:

    • generate_image принимает только image_url — публичный https (MediaTools.kt:93). Фото из чата — локальный файл, агенту нечего передать.
    • list_media_models не отдаёт acceptsImageReference — агент не может выбрать модель, умеющую редактировать по фото.
    • Студийный пайп референсов шлёт несуществующий ключ input_urls (MediaStudioViewModel.kt:99) — неизвестные параметры игнорируются, референс молча выбрасывается. Для локальных файлов контракт требует *_base64 (data:<mime>;base64,…) или Files API (см. docs/knowledge/media-providers/plusvibe.md, раздел «Свои файлы»).

    Дизайн-спека (пункты 1 и 5)

    Общий стиль: тёмный «холст» с точечной сеткой, стеклянные панели (surface с альфой + tonalElevation), скругления 12-16.dp, акцент — primary. Все действия — иконки без подписей (доступность: contentDescription на русском). material-icons-extended уже в зависимостях (composeApp/build.gradle.kts:96); есть и свои composeResources/drawable/ic_*.xml. Базовый компонент — SmallIconButton (ui/chat/composables/SmallIconButton.kt), 36.dp круг.

    Нижняя панель (над системным краем)

    Канвас

    • Фон: surface → тонкая точечная сетка (рисуется в Canvas, шаг 24.dp, точки onSurfaceVariant с альфой ~0.15), пан/зум как сейчас.
    • Элементы: скругление 12.dp, тень (2-6.dp), у выбранного — рамка primary 2.dp + угловые маркеры (drag для resize — на десктопе; на тач — пинч через transformable, уже есть).
    • Прогресс генерации: на месте будущего элемента — карточка-скелетон (шиммер + имя модели + таймер), не одинокий спиннер по центру.
    • Контекстное меню: скруглённая стеклянная Surface под точкой тапа, строки «иконка + подпись», координаты = element + canvasOffset (исправить баг). Действия: Вперёд/Назад (FlipToFront/FlipToBack), Дублировать (ContentCopy), Референс (Link/Bookmark), В галерею (SaveAlt), Удалить (Delete, красный), Закрыть.
    • Пустое состояние: крупная иконка + 2 строки подсказки + стрелка на нижнюю панель.

    Выбор моделей

    • Не LazyColumn 96.dp, а bottom-sheet (ModalBottomSheet): секции «Изображения»/«Видео», строка = имя + цена-бейдж (secondaryContainer)
    • отметка выбора; выбранная строка: фон primaryContainer, текст onPrimaryContainer (исправление цвета), справа Check.
    • В студии текущая модель показана чипом рядом с кнопкой «Создать» (тап — тот же sheet).
    • MediaModelsSettings.kt: те же цвета (onPrimaryContainer), бейджи цен.

    Параметры генерации

    FilterChip с selected (сейчас AssistChip без подсветки), параметры брать у выбранной модели; неизвестные ключи не отправлять.

    Ошибки

    Не красная строка, а Snackbar + иконка; текст на русском, с действием («Повторить», «Открыть настройки»), если причина — ключ/модель. Ошибка полностью логируется (см. логирование).

    Фазы

    P0 — корректность (до любых перерисовок)

    1. Логирование медиа-слоя. Минимальный expect-механизм: в commonMain объект MediaLog { fun d/i/e(tag, msg, throwable?) }, actual через android.util.Log (androidMain), println с тегом (остальные). Точки: загрузка каталога (число моделей), каждая подача (модель, размер тела, наличие референсов), каждый ответ опроса (статус, цена), каждая ошибка (полный стек). Файлы: новый media/MediaLog.kt + expect/actual по образцу Platform.*; вызовы в PlusVibeMediaProvider, MediaGenerationRepository, MediaStudioViewModel, MediaTools.
    2. Видимые ошибки. MediaStudioViewModel.error → Snackbar в студии (хост: MediaStudioScreenFull получает SnackbarHostState), тексты на русском из MediaException (mapError уже маппит коды). Для InvalidKey — действие «Открыть настройки сервисов».
    3. Убрать второе поле ввода. ChatScreen.kt:1456: if (!isSandboxOpen) → if (!isSandboxOpen && !isMediaOpen).
    4. Надёжность «с нуля». В generateImage/generateVideo: если модель в настройках пуста — автоматически брать первую доступную из каталога и сохранять (сейчас только фолбэк в памяти); пустой промпт — подсветить поле и подсказку, не тихий return. В AppModule/ AgentToolSet для ключа брать активный инстанс чата, а не firstOrNull() (проверить, как его отдаёт AppSettings/ChatViewModel, например выбранный сервис в uiState).
    5. Баги канваса. menuOffset += canvasOffset; убрать заглушку «Сохранить набор» (или реализовать: сериализовать список референсов в JSON и сохранить); ParamChips — параметры выбранной модели.
    6. Удалить мёртвый MediaStudioScreen.kt; починить docs/features/media-studio.md (Key Files, поведение референсов, пункт про вход в студию).

    P1 — референсы (пункты 2 и 3)

    1. Модель данных. MediaModels.kt: data class MediaReference(val url: String? = null, val base64DataUri: String? = null, val localPath: String? = null, val isVideo: Boolean = false); поле references: List<MediaReference> в MediaJobRequest.
    2. Провайдер. PlusVibeMediaProvider.buildGenerateBody: для каждой ссылки подобрать ключ по каталожным params выбранной модели (пересечение с IMAGE_REFERENCE_KEYS/VIDEO_REFERENCE_KEYS): image_url/reference_image_urls для публичных https, парные *_base64 (полный data:<mime>;base64,…) для локальных байтов. Если модель не принимает вход — ошибка MediaException.BadRequest("Модель … не принимает референс") до отправки. Размер: локальный файл > 8 МБ — сначала POST /v1/files (дописать в провайдер) и использовать *_file_id (контракт в plusvibe.md).
    3. Студия. Полоска референсов над нижней панелью: миниатюры 40.dp с крестиком удаления; источники — (а) «Как референс» из меню элемента (уже есть, направить в новый тип), (б) кнопка «+» в полоске — файловый пикер (тот же rememberFilePickerLauncher), (в) перетаскивание элемента. При генерации ViewModel кладёт набор в MediaJobRequest.references (удалить input_urls).
    4. Инструменты агента. MediaTools.generateImageTool:
    5. параметр reference_image (путь вложения/канваса или публичный https); локальный путь → читать байты (readAppStorageBytes/ PlatformFile) → base64 data-URI;
    6. авто-выбор модели с acceptsImageReference, если передан референс, а выбранная модель его не принимает (брать из каталога);
    7. list_media_models: добавить acceptsImageReference, acceptsVideoReference в выдачу.
    8. Системный промпт агента: в медиа-раздел добавить, что агент умеет генерировать/редактировать изображения и видео по приложенному фото через generate_image(reference_image=…), и должен использовать вложение пользователя, когда просят «улучшить фото», «сделать меня где-то». (Раздел про инструменты в docs/features/system-prompts.md и соответствующий рантайм-файл — найти по tools.md/AgentToolSet.)

    P2 — редизайн (пункты 1 и 5)

    Разбить MediaStudioScreenFull.kt на компоненты (по образцу из docs/features/media-studio.md, теперь настоящие):

    • ui/media/MediaStudioTopBar.kt — 4 иконки-оверлея.
    • ui/media/MediaCanvas.kt — сетка, элементы, выбор, шиммер-прогресс.
    • ui/media/MediaContextMenu.kt — стеклянное меню под точкой тапа.
    • ui/media/MediaDock.kt — промпт-поле, режим, референсы, «Создать», иконки озвучки/голоса/агента, чип текущей модели.
    • ui/media/MediaModelSheet.kt — bottom-sheet выбора модели (общий для студии; в настройках — тот же ModelPicker с исправленными цветами).
    • ChatScreen.kt — иконка медиа в TopBar (ui/chat/composables/TopBar.kt), чтобы студия открывалась и при непустой истории; кнопку в EmptyState оставить.

    Проверить контраст всех текстов на тёмном/светлом фоне (сетка, цены, подсказки) — в том числе для светлой темы приложения.

    P3 — проверка (обязательно для «готово»)

    1. ./gradlew spotlessApply → :screenshotTests:updateScreenshots → :composeApp:desktopTest (CI-порядок; если скриншоты студии входят в goldens — обновить осознанно).
    2. Визуально (модель со зрением): запустить ./gradlew :composeApp:run, снять и разобрать кадры: пустой канвас; sheet моделей (выбор, цены, цвета); полоска референсов; контекстное меню; лайтбокс; ошибка без ключа; нижняя панель (иконки без текста); канвас с несколькими элементами. Сверить с дизайн-спекой выше; список расхождений — в этот файл разделом «Замечания визуальной проверки».
    3. Сборка и телефон: ./gradlew :androidApp:assembleFossRelease (KEYSTORE_* из androidApp/foss-release.keystore, см. AGENTS.md), затем adb -s 192.168.1.210:44055 install -r <apk>. На телефоне проверить: генерация «с нуля» (видна ошибка или результат), референс — «улучшить моё фото и сделать меня возле фонтана в Дубае» (сценарий пользователя), выбор модели с ценой, отсутствие второго поля ввода, иконки без текста. Логи после теста: adb shell logcat -d --pid=$(adb shell pidof com.pusios.pots) | grep -i Media.
    4. Синхронизировать docs/features/media-studio.md (поведение + Last verified), при изменении инструментов — docs/features/tools.md; запись в CHANGELOG.md (Unreleased).

    Definition of done

    • Изображение «с нуля» создаётся и с ключом, и с внятной ошибкой без него; каждая ошибка видна и залогирована.
    • Фото-референс работает: студия (полоска) и агент (вложение чата), сценарий «я возле фонтана в Дубае» даёт изображение.
    • В медиа-режиме одно поле ввода.
    • Студия соответствует дизайн-спеке: иконки без текста, канвас с сеткой/ рамками/шиммером, sheet моделей с корректными цветами выбора.
    • Вход в студию доступен при непустом чате.
    • Тесты/формат/скриншоты зелёные; сборка ставится на телефон поверх текущей (одна подпись).
