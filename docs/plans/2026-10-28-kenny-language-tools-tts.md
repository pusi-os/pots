## 1. Кенни (PARKA)

Проблемы (подтверждены рендером Paparazzi, `screenshotTests/.../PotsikDebugTest.kt`):
- Щель-«окно» капюшона задана в сырых пикселях `hh+2..hh+12` без `S()`, поэтому на
  любом масштабе кроме 1.0 она не совпадает с глазами: глаза полностью скрыты.
- Из-за дробного `hh` (bob) строки у границы окна «перещёлкиваются» между
  «в окне/не в окне» — мерцание каймы.
- Очки рисуются на лице и выглядывают из щели — для капюшона должны быть выключены
  всегда.

Решение:
- `PotsikCostumes.drawParka()`: границы окна в целых строках относительно `oy`,
  т.е. `dy2 ∈ [-S(3) .. S(7)]` (окно = юниты 5..15: кайма глаз видима, рот и нос
  скрыты), ширина `S(14)`; кайма-линии на тех же целых строках. Мерцание исчезает,
  т.к. условие стало чисто целочисленным.
- `PotsikBody`: для PARKA не рисуем нос (в окне только глаза) и всегда трактуем
  `glassesOn = false`.
- «Потсики» в настройках: при Кенни переключатель очков неактивен с пояснением.
- Проверка: рендеры в двух масштабах, обновление золотых образов.

## 2. Вылет «Инструментов» и провайдер локальных моделей

Первопричина (найдена): в рабочем дереве (незакоммичено) из `AppModule.kt` удалена
регистрация `single<LocalInferenceEngine?> { createLocalInferenceEngine() }`, а
`RemoteDataRepository` переведён на `getOrNull()`. Из-за этого:
- `koinInject<LocalInferenceEngine>()` в `ToolsSettings.VectorStorageSection` падает
  `NoDefinitionException` → вылет при открытии «Инструментов»;
- `isLocalInferenceAvailable()` всегда `false` → провайдер «Local Model» исчезает из
  «Сервисов» на всех платформах.

Решение (минимальное):
- Вернуть регистрацию в `AppModule` и `get()` в `RemoteDataRepository`.
- `ToolsSettings`: `koinInject<LocalInferenceEngine?>()`; при `null` секция
  векторного поиска рендерится неактивной с текстом «инструмент не поддерживается
  на этом компьютере».
- «Сервисы»: он-девайс сервис больше не прячется из списка добавления/настроек —
  карточка рендерится неактивной с тем же сообщением, когда движка нет.

## 3. Язык интерфейса

- `AppLanguage { SYSTEM, ENGLISH, RUSSIAN }` в `AppSettings` (ключ + StateFlow).
- Корень приложения: `CompositionLocalProvider(LocalComposeEnvironment provides …)`
  (CMP 1.12: официальный способ переопределить локаль ресурсов) + `key(language)`
  для полной рекомпозиции.
- Все точки, читающие `Locale.current.language` (бантер Потсика, подписи образов,
  пресеты характера, имена фонов), читают переопределение.
- «Настройки → Общие»: карточка «Язык интерфейса» перед секцией темы;
  варианты: Системный (по умолчанию) / Русский / English.

## 4. Ollama через openai-compatible

Приложение уже умеет: `OpenAICompatible` с базой по умолчанию
`http://localhost:11434/v1` — список моделей `/v1/models`, чат `/v1/chat/completions`,
инструменты работают. Добавляем только скрипты:

- `scripts/ollama-setup.sh` — детект установки/запуска, установка с официального
  релиза под ОС/архитектуру (Linux `tar.zst` в `~/.local`, macOS `ollama-darwin.tgz`,
  Windows — по инструкции), старт `ollama serve`, проверка `/api/version`.
- `scripts/ollama-models.sh` — `list` (что стоит), `pull <модель>` с прогрессом,
  `recommended` (короткий список актуальных небольших моделей), подсказка какие id
  вписать в openai-compatible в настройках.

## 5. STT/TTS: секция в «Общих» + движок Piper (после пп. 1–4)

Задача (дописана по просьбе пользователя):
- Секция «Озвучивание (TTS/STT)» в «Настройки → Общие»:
  - выбор движка: системный (по умолчанию, как сейчас) и Piper;
  - для системного — выбор голоса из доступных системе;
  - для Piper — выбор языка, затем голоса (все доступные для языка), загрузка
    модели с прогресс-баром и докачкой при обрыве, персистентное хранение.
- Piper встроен в приложение: при выборе движка автоматически скачивается и
  разворачивается среда Piper (бинарник + espeak-ng-data по ОС), модель голоса
  (`*.onnx` + `*.onnx.json` с HuggingFace `rhasspy/piper-voices`) качается в
  хранилище приложения и используется для TTS в чате и всюду, где нужен голос.
- Лучшие практики: докачка через HTTP Range, проверка размера/чек-суммы, загрузка
  в temp + атомарная замена, запуск бинарника как child process (никакого root),
  кэш моделей в `~/.pots/piper/`, выбор голоса по языку интерфейса пользователя.

Дизайн (кратко):
- `TtsEngineId { SYSTEM, PIPER }` + настройки в `AppSettings` (движок, голос Piper,
  голос системный).
- Desktop: `PiperVoiceManager` (скачивание/распаковка/реестр голосов) +
  `PiperTtsInstance : TextToSpeechInstance` (генерация wav через процесс piper,
  воспроизведение через javax.sound). Мобильные остаются на системном движке.
- Каталог голосов: `voices.json` из релиза Piper (имя, язык, качество, размер,
  URL) — группировка по языку, показ всех доступных.

Критерии приёмки: переключение движка сразу влияет на озвучку чата; обрыв загрузки
продолжается с места остановки; выбранный голос переживает перезапуск.
