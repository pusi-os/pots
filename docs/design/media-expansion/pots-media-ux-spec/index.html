    0. Принципы и отправные точки

    Текущий стиль (не менять, только наследовать):

    • Стеклянные капсулы: Surface(alpha ≈ 0.9, tonalElevation), скругления 22/20/16/14/12/11 .dp.
    • Чипы тулбара: RoundedCornerShape(12.dp), labelMedium, паддинг 10.dp × 6.dp, фон tertiaryContainer.
    • Сегмент режимов: капсула 14.dp, кнопки со скруглением 11.dp, иконка 18.dp в паддинге 7.dp; активная — primaryContainer, неактивная — прозрачная, onSurfaceVariant.
    • Элемент канваса: 232 .dp (CANVAS_ELEMENT_SIZE_DP), скругление 12.dp, выделение — кольцо 2.dp primary; панель операций — капсула у нижнего края.
    • Интерактив: handCursor() на всём кликабельном; contentDescription на русском у каждой иконки.

    Правила дизайна:

    1. Дизайн — как вещь работает: каждая операция видна только тогда, когда нужен её объект (контекстные панели — паттерн CapCut).
    2. Простота: одна главная дорожка таймлайна + аудиодорожка в v1; мультитрек — позже.
    3. Ничего не терять: промпт, параметры и референсы не очищаются ни при смене режима, ни при ошибке.
    4. Среда — десктоп (Omarchy/Hyprland): ховер-состояния, клавиатура, точность мыши; тач-жесты остаются вторичными (приложение KMP).
    5. Все подписи — на русском.

    1. Третья кнопка «Аудио» в тулбаре режимов

    • ModeSegment становится трёхкнопочным: Изображение (Icons.Filled.Image), Видео (Icons.Filled.Movie), Аудио (mode-audio.svg — музыкальная нота, без подписи).
    • Геометрия новой кнопки — ровно как у существующих: иконка 18.dp, паддинг 7.dp, активная = primaryContainer/onPrimaryContainer, неактивная = прозрачная/onSurfaceVariant. Третья кнопка не меняет ширину капсулы — только добавляет сегмент.
    • contentDescription = "Режим аудио".
    • Состояние isVideoMode: Boolean заменить на enum MediaMode { IMAGE, VIDEO, AUDIO }; переключение — клик по неактивному сегменту (как сейчас).
    • При переключении меняется: набор чипов (§2), плейсхолдер дока — «Опиши звук или речь…» (для музыки — «Опиши трек: жанр, настроение…»), фильтр шита моделей (kind=audio|music), поведение канваса (§3).
    • Черновик промпта хранить отдельно на каждый режим: переключение режимов текст не стирает.
    • Аудио-режим делится на два флоу — «Озвучить текст» (TTS) и «Создать музыку» (музыка + эффекты): первый тап включает режим с запомненным флоу, повторный тап по активному сегменту открывает выбор флоу — §13.

    2. Чипы параметров аудио (вместо разрешения/соотношения сторон)

    В режиме аудио чипы разрешения и соотношения сторон скрываются; вместо них — чипы, построенные из осей модели каталога (axes), универсально по модели (правила рендера осей сверены со справкой @pifiya §4.2):

    • Порядок приоритета на тулбаре: duration → voice → response_format/output_format → language → прочие select-оси. Максимум 4 чипа в ряду, остальные — в шите параметров (паттерн MediaParamSheet).
    • select с ≤ 6 опциями — чип-строка; select с большим списком (голоса 9–30) — чип с текущим значением, открывающий шит выбора. toggle — чип-переключатель (активный = primaryContainer). Короткие text (bpm, speed) — инлайн-поле в шите; длинные (lyrics, style, instructions, script) — многострочное поле в раскрытии шита.
    • Технические оси (seed, sample_rate, bitrate, channel, stability, similarity_boost) — только в «Ещё», на тулбар никогда.
    • Вид чипа — существующий TopBarChip; текст чипа = короткое значение: «30 с», «Rachel», «MP3», «RU». Полный лейбл оси — в шите. Обязательные оси (required) — первыми.
    • Ось duration показывать только если она есть у модели: у TTS цена считается за символы, и чип длительности был бы фикцией.

    Цена и отправка:

    • Бейдж цены в шите: от {цена} ₽ {единица} — строка unit каталога как есть («за 1000 символов», «за трек», «за секунду», «за файл», «за озвучку»); десятичный разделитель — запятая (локаль ru). У priceStatus=estimate — префикс «≈» и подсказка из priceWarning.
    • Перед отправкой — котировка POST /api/media/price; кнопка дока показывает итог: «Создать · ≈ 12 ₽». Для тарифицируемых по входу моделей (за 1000 символов / за секунду) в generate уходят quote_id + max_price_rub. Если цена не изменилась при повторе — не переспрашивать.
    • Если у модели есть tiers (цена зависит от выбранных чипов) — бейдж пересчитывается при смене чипа; нет совпадения → «от» по fromRub.

    Шит моделей аудио (состав и дефолты — по справке @pifiya §4.1):

    • Три группы с заголовками, внутри — сортировка по цене «от»: Голос (19 TTS в каталоге; в шите v1 — 18, см. §14), Музыка (5), Эффекты (4). Отдельный пункт «Мой голос» — модели с клонированным голосом (voice_id через POST /api/media/voices).
    • Дефолты: голос — gpt-4o-mini-tts; музыка — suno (маршрут suno:white); эффекты — elevenlabs-sound-effects-v2.
    • Никогда не показывать в шите генерации: STT/аналитику (вход audio_url), музыкальные трансформации с аудио-входом и утилиты — итого 29 моделей вне v1.
    • Пометки на карточках: «только английский» (kokoro-tts), «до 300 символов за запрос» (chatterbox-tts), «уточняется по длительности» (mirelo-sfx-2).
    • Состав шита определяется активным аудио-флоу: группы разнесены по флоу, плюс локальная группа у TTS — §14.

    3. Аудио-элемент на канвасе (плеер)

    • Карточка того же размера 232 .dp, фон surfaceVariant, скругление 12.dp, выделение — то же кольцо 2.dp primary. Сетка канваса остаётся однородной.
    • Наполнение карточки: волновая дорожка по всей ширине (пики onSurfaceVariant 40 %, проигранная часть — primary), по центру круглая кнопка воспроизведения 52.dp primaryContainer (форма кнопки «Создать» в доке), снизу время 0:12 / 0:30 (labelSmall, как в видеоплеере).
    • Воспроизведение — внутри приложения (без системного плеера): expect/actual по образцу PlatformVideoView (десктоп — media3/JavaSound, Android — MediaPlayer).
    • Управление:
    • Перемотка: клик/драг по волне = переход к позиции; тонкий Slider под волной — всегда при выделении. Тач-цель скраббера ≥ 44 .dp независимо от толщины линии (важно для KMP-тача на десктопе/планшете).
    • ±10 с: кнопки rewind.svg / forward.svg в панели выделенного элемента.
    • Скорость: пресеты 0.5× / 0.75× / 1× / 1.25× / 1.5× / 2× чипами (активный — primaryContainer); в карточке — только в панели выделения, полный набор — в редакторе.
    • Громкость: иконка volume.svg + горизонтальный Slider 0–100 %; клик по иконке = mute (иконка приглушается до 40 % альфы).
    • Панель выделенного аудио-элемента (те же ElementChip): воспроизведение/пауза, «Редактировать» (§4), «Прикрепить к видео» (§6.4), «В таймлайн» (§7), SaveAlt «Сохранить в галерею», Delete. Операция «Использовать как референс» для аудио не показывается.
    • Скелетон генерации аудио = существующий GenerationSkeleton (без изменений).

    4. Редактор аудио

    Вход: чип «Редактировать» в панели выделенного аудио-элемента. Полноэкранный шит (по образцу лайтбокса): шапка (название, длительность), волна на всю ширину, управление снизу.

    • Волна: зум (Ctrl+колесо / пинч), плейхед, линейка времени (шаг 5/10 с в зависимости от зума). Выделение = драг по волне; у выделения ручки по краям (как трим-хэндлы клипов в CapCut). Волна показывается потому, что по ней действуют (ищут тишину, режут ложный старт); для чистого воспроизведения без правок достаточно прогресс-бара.
    • Обрезка: «Обрезать до выделения» (trim.svg) — остаётся только выделенный диапазон; отдельно «Обрезать начало/конец до плейхеда». Обрезка неразрушающая: обрезаются края клипа за ручки, скрытое можно оттянуть назад; все правки — в стек отмены (без ограничений в рамках сессии, паттерн настольных аудиоредакторов).
    • Разрезать: плейхед + «Разрезать» = два независимых клипа (паттерн CapCut Split).
    • Скорость: слайдер 0.25–4.0 + пресеты 0.5/1/1.5/2; тумблер «Сохранять тон» (вкл. по умолчанию — для речи, чтобы не было «бурундука»). Изменение скорости — предпрослушивание без переписывания файла; в файл рендерится только при экспорте.
    • Склейка 2+ треков: кнопка «Добавить трек» (+) — выбор из аудио-элементов канваса, журнала или файла. Треки — вертикальный список строк со своей волной, тримом и громкостью; порядок = перетаскивание; склейка = последовательное соединение сверху вниз (без микширования — микс выйдет в следующих версиях). Кнопка «Предпросмотр склейки» проигрывает результат.
    • Сравнение с оригиналом: в шапке редактора переключатель «Оригинал / Результат» (A/B) — обработанное всегда слышно рядом с исходным.
    • Экспорт: «Экспорт» → чипы формата (MP3 / WAV), затем «Сохранить в галерею» и/или «Добавить на канвас как новый элемент». Рендер локальный, с LinearProgressIndicator. Фейды (вход/выход) — не в v1; когда появятся, у каждого своя длительность с явным нулём («0 = выключено»), без скрытых дефолтов.
    • Закрытие с несохранёнными правками — подтверждение: «Сохранить изменения?» → «Сохранить» / «Не сохранять» / «Отмена».

    5. Рисование карандашом на изображении

    Вход: чип «Карандаш» (brush.svg) в панели выделенного изображения.

    • Полноэкранный режим: изображение на весь экран; внизу — стеклянная капсула инструментов (как верхняя капсула тулбара):
    • Кисть: в v1 одна кисть с тремя пресетами толщины (тонкая 2, средняя 6, толстая 14 .px) — иконка line-weight.svg.
    • Цвет: 8 свотчей (чёрный, белый, красный, оранжевый, жёлтый, зелёный, синий, фиолетовый) + индикатор текущего. Кастомный цветовой круг — не в v1.
    • Толщина: слайдер 1–32 .px с круглым превью на ползунке.
    • Отмена: undo.svg — отмена по штрихам (стек); «Очистить всё» — с подтверждением.
    • Отмена режима: крестик — сбрасывает штрихи (подтверждение, если штрихи есть).
    • Применение: apply.svg — штрихи запекаются в копию; оригинал генерации не трогается; копия появляется на канвасе рядом и связана с исходной задачей (недеструктивный паттерн).
    • Штрихи хранятся векторно (путь, цвет, толщина) и рисуются Canvas поверх изображения со сглаживанием (квадратичные кривые по точкам).
    • Десктоп: ЛКМ — рисовать, Ctrl+Z — отмена; тач/стилус поддерживаются тем же жестом.

    6. Операции редактирования изображений/видео на канвасе

    Каждая операция открывается полноэкранно с предпросмотром и парой «Применить» / «Отмена». Исходник никогда не перезаписывается: результат — новый элемент, связанный с исходной задачей.

    • Обрезка (crop.svg): рамка с ручками, сетка третей; чипы соотношения: Свободно · 1:1 · 4:3 · 3:4 · 16:9 · 9:16. Для видео — та же рамка (кадрирование кадра, не времени; время режется в таймлайне §7).
    • Размер (resize.svg): существующие жесты масштаба + шит: поля «Ширина/Высота» в .px, тумблер «Сохранять пропорции» (вкл. по умолчанию), пресеты 512 / 1024 / 2K. Определяет разрешение экспорта элемента.
    • Наложение (overlay.svg): перетащи элемент B на элемент A → чип «Наложить»: B становится дочерним слоем A — позиция и масштаб считаются от рамки A, двигается вместе с A; zIndex внутри родителя; «Открепить» возвращает самостоятельность. В панели наложения — слайдер прозрачности 0–100 % (по умолчанию 100 %).
    • Аудиодорожка на видео (audio-track.svg): чип «Музыка» в панели выделенного видео → выбор: аудио-элементы канваса, журнал (kind=audio|music), импорт файла. Прикреплённая дорожка отображается волновой полосой 24.dp под элементом; доступны громкость, «Заменить», «Убрать». Дорожка следует за клипом при сборке в таймлайн (§7).

    7. Таймлайн — сборка видео из элементов канваса

    Вход: пятая кнопка верхней капсулы тулбара — timeline.svg, подпись-подсказка «Собрать видео». Открывает нижний ящик: сверху предпросмотр текущего кадра, снизу лента (компоновка CapCut: плейхед зафиксирован по центру, лента прокручивается под ним — так удобнее и мышью, и пальцем).

    • Добавление: чип «В таймлайн» (add-clip.svg) в панели выделения любого элемента; плюс + в конце ленты — выбор из канваса/журнала (паттерн CapCut/VN).
    • Клипы: изображение = стоп-кадр с чипом длительности (по умолчанию 3 с; меняется перетаскиванием правого края); видео = полоса миниатюр с реальной длительностью; аудио = волновая полоса в нижней дорожке.
    • Дорожки в v1: одна главная видеодорожка + одна аудиодорожка. Мультитрек — будущая версия (простота прежде всего).
    • Операции на ленте: перестановка перетаскиванием; трим за края (у видео — покадровый при зуме); удаление; клик по стыку клипов = слот перехода: «Нет» (жёсткая склейка, по умолчанию — правильный дефолт) или «Затемнение» 0.3/0.5 с. Больше переходов не нужно: частые эффекты удешевляют монтаж.
    • Плейхед: скраббинг = перетаскивание ленты; зум масштаба времени — Ctrl+колесо (десктоп) / пинч (тач); предпросмотр всегда синхронен с плейхедом.
    • Аудиодорожка: треки выкладываются последовательно, двигаются перетаскиванием; громкость — слайдер на выбранном треке. Автоподгонка не нужна — точность даёт зум.
    • Экспорт: «Экспорт видео» → шит: разрешение 720/1080, fps 24/30, ориентировочный размер; рендер с LinearProgressIndicator и кнопкой «Свернуть» (работа со студией продолжается, в верхней капсуле появляется бейдж «Сборка видео…», клик — вернуться к прогрессу). Результат — новый видео-элемент на канвасе + запись в журнале.
    • Связь: субтитры к ролику — §10; проект таймлайна сохраняется автоматически — §12.

    8. Состояния ошибок

    Единый паттерн для любой неудачи (генерация, скачивание, экспорт, импорт). Состав (по канону AI error states):

    1. Суть — что случилось, одним человеческим предложением; без кодов и трассировок.
    2. Причина — категория: сеть / провайдер / лимиты / фильтр контента / параметры / файл.
    3. Спасение — 1–3 кнопки: основная «Повторить», вторая — целевое действие, третья — «Скрыть/Отмена».
    4. Сохранённый ввод — промпт, параметры и референсы никогда не очищаются ошибкой.

    Размещение:

    • На канвасе вместо скелетона — карточка ошибки: фон errorContainer, иконка error.svg, заголовок + текст + кнопки.
    • В журнале неудачная запись получает бейдж ошибки и кнопку «Повторить».
    • Мелкие сбои (галерея, буфер обмена) — Snackbar с действием, без карточек.

    10. Субтитры — «в момент произношения»

    Вход: тумблер-кнопка «Субтитры» (subtitles.svg) на ленте таймлайна (§7), по умолчанию выключен.

    Тайминги:

    • Источник — речь аудиодорожки таймлайна или звукового видеоклипа. Свой/сгенерированный файл уходит в STT через POST /v1/files → audio_file_id (публичного HTTPS у локальных файлов нет — контракт, справка @pifiya §5).
    • Модель по умолчанию — whisper-large-v3-turbo (0.02 ₽/мин, мультиязычная); альтернатива с таймкодами фраз — qwen3-asr-0.6b (0.02). Для русского с несколькими спикерами — universal-2.
    • Бесплатный путь: если озвучка сгенерирована voice-clone-tts или inworld-realtime-tts-1-5-max, тайминги слов приходят вместе с озвучкой — субтитры без STT-запроса; в шите этих моделей подсказка «Тайминги слов включены».
    • Язык — автоопределение; .en-варианты моделей не применять к не-английскому аудио (переведут вместо расшифровки).
    • STT-задание идёт тем же контрактом, что генерация: очередь и журнал, котировка «за минуту» в бейдже до отправки (§2, бейдж-правила @kodi).

    Результат — список реплик {start, end, text}; хранится в проекте (§12). Реплики редактируются: тап по реплике → шит с текстом и таймкодами; «Пересоздать субтитры» — повторный STT, старые реплики не стираются до подтверждения новых.

    Стиль (паттерны HyperFrames, согласованы планом):

    • Три пресета по тону: «Нейтральный» (чистый sans 600, белый текст на плашке 60 % — дефолт), «Динамичный» (плотный 800, появление по словам, 2–3 слова), «Спокойный» (мягкий фейд, 4–6 слов).
    • Группировка по естественным фразам; разрыв на границах предложений и паузах ≥ 150 мс; на экране одна группа за раз.
    • Позиция: горизонталь — низ кадра (отступ 5–7 % высоты); вертикаль — 25–30 % от низа; не перекрывать лицо (при конфликте — сдвиг выше). Кегль автоподбирается под ширину кадра — переполнения нет.

    Поведение: тумблер меняет предпросмотр сразу, без рендера. В экспортном шите (§7) — чекбокс «Вшить субтитры» (по умолчанию вкл., если субтитры включены). В v1 субтитры вшиваются в кадр (hardsub); отдельная дорожка softsub — будущая версия. Ошибка субтитров — карточка §8; реплики и проект не теряются (§12).

    11. Аудио-реактивный клип одной кнопкой (без ЛЛМ)

    Вход: выделить аудио-элемент на канвасе (импорт или генерация) → чип «Сделать клип» (movie-filter.svg). Весь поток детерминированный: ни одного запроса к ЛЛМ, стоимость 0 ₽ — только локальная обработка (котировка не запрашивается, бейдж «бесплатно»).

    Шит клипа:

    • Визуальный ряд: мультивыбор фото/видео с канваса и журнала; порядок — перетаскиванием. При пустом выборе клип собирается на абстрактном фоне (градиент из доминирующих цветов обложки трека) — клип возможен всегда.
    • Стиль — три пресета: «Пульс» (минимальный, акцент на такт), «Свечение» (мягкие пересветы), «Кино» (затемнения + плавный зум). Не больше трёх — то же правило, что для переходов §7.
    • Длительность = длительность трека, не редактируется: клип монтируется под музыку.

    Анализ звука — один раз, локально: из трека предварительно извлекаются огибающие полос (бас, середина, верха, общая амплитуда) с покадровой частотой рендера. Никакого анализа в реальном времени при воспроизведении.

    Эффекты (паттерны HyperFrames: звук управляет поведением, контент ведёт картинку):

    • бас → масштаб кадра 1.00–1.06 (пульс на такт);
    • верха → интенсивность свечения оверлеев;
    • общая амплитуда → лёгкий дрейф зума/прозрачности и сдвиг температуры;
    • середина → мягкий зум-переход между сценами.
    • Запрещено (антипаттерны): эквалайзер-бары, спектр-анализаторы, радужные циклы, типовые частицы.

    Монтаж: сцены = выбранные элементы в заданном порядке; смены сцен выравниваются по пикам энергии (детект по огибающей, без ЛЛМ); переходы — жёсткая склейка или затемнение 0.3 с (§7). Аудиодорожка результата = выбранный трек.

    Предпросмотр и рендер: в шите — быстрый предпросмотр первых 10 с; «Собрать клип» → стандартный прогресс («Свернуть», бейдж в капсуле — как экспорт §7). Результат — новый видео-элемент на канвасе + запись в журнале (пометка «клип, 0 ₽»). Ошибка рендера → строка «Рендер видео» (§8), проект сохранён (§12).

    12. Проекты медиа-студии: сохранение, импорт, экспорт

    Модель: Проект = элементы канваса (позиции, zIndex, трансформации, наложения §6) + таймлайн (клипы, переходы, аудиодорожка §7) + субтитры со списком реплик (§10) + выбранный аудио-флоу (§13) + черновики промптов и чипов на каждый режим и флоу (§1, §13). Связь с журналом — по id генераций. Формат — один файл .potsproj (JSON) с полем schemaVersion.

    Автосохранение:

    • После каждой завершённой операции (добавлен элемент, применена операция, изменён таймлайн), дебаунс ~2 с, в локальное хранилище; модалок «сохранить» нет.
    • Индикатор — ненавязчивая отметка «Сохранено» в верхней капсуле (появляется и гаснет), действия не требует.

    Меню «Проекты» (folder-open.svg) в верхней капсуле:

    • Список локальных проектов: имя (авто «Проект, 13 ноя» — переименовывается), дата, миниатюра первого элемента/кадра.
    • Действия: Открыть · Дублировать · Переименовать · Экспортировать (project-save.svg) · Удалить (подтверждение с именем проекта).

    Экспорт/импорт:

    • «Экспортировать проект» → файл .potsproj; вариант «со связанными медиа» — zip (проект + файлы элементов) для переноса между устройствами.
    • Импорт из файла: проверка schemaVersion; неизвестная версия → карточка §8 «Формат не поддерживается» с текстом про версию. Импортированный проект открывается как новый, существующие не затираются.

    Гарантии: исходники не перезаписываются (§6); ошибка рендера/экспорта не теряет проект — строка «Рендер видео» (§8) обещает сохранённый проект именно благодаря этому разделу; повторное открытие — из «Проектов». Синхронизации/облака в v1 нет: только локальное хранилище и файлы.

    13. Два флоу аудио: «Озвучить текст» и «Создать музыку»

    Аудио-режим делится на два флоу. Контракт взаимодействия (согласован с @kodi/@linus, два такта):

    • Первый тап по «Аудио» включает режим с запомненным последним флоу; повторный тап по уже активной кнопке открывает компактный выпадающий выбор.
    • Выпадающий выбор — в стиле существующих меню/шитов студии, без новых слоёв: два пункта с иконками — record-voice-over.svg «Озвучить текст» и library-music.svg «Создать музыку»; активный пункт отмечен.
    • Визуальное отличие активного флоу: плейсхолдер дока, набор чипов и состав шита моделей (см. ниже и §14).
    • Выбор флоу хранится в MediaSettings/модели проекта (§12), не во временном remember (требование @linus); ошибкой не очищается (§8).

    Флоу:

    • «Озвучить текст» (TTS) — плейсхолдер «Введите текст для озвучки…»; вход — текст любой длины (§17); модели и параметры — §14–§15.
    • «Создать музыку» — плейсхолдер «Опиши трек: жанр, настроение…»; музыка может быть со словами: текст песни задаётся в промпте (расширенное поле §17), модели с поддержкой lyrics — suno, lyria-3-5, acestep-v15-xl-sft; у suno ось instrumental — чип «Без слов».
    • Черновики промпта — раздельно на режим и флоу (§17): переключение не стирает текст.

    14. Шит моделей по флоу

    Состав шита определяется активным флоу (§13) — группы §2, разнесённые по флоу:

    • «Озвучить текст»: группа Голос (облачные class=tts: в v1 показываются 18 из 19 — mimo-v2-5-tts-voiceclone скрыта, решение в §15) и внизу, под разделителем, группа «Локально · 0 ₽».
    • «Создать музыку»: группы Музыка (class=music, 5) + Эффекты (class=sfx, 4). suno-replace-section (замена фрагмента трека) требует source_task_id ранее сгенерированного трека — показывать только при наличии истории Suno-задач (согласовано ещё в справке §4.1).
    • Бейджи цен с единицами и котировка — правила §2 без изменений (включая решение @kodi/@linus: metered-модели котируются перед отправкой, фикс-цены показывают бейдж по fromRub).
    • Дефолты: TTS — gpt-4o-mini-tts; музыка — suno (suno:white); эффекты — elevenlabs-sound-effects-v2.

    Группа «Локально · 0 ₽» (честный состав — по исследованию @pifiya §4):

    • Только Android: Piper «Ирина» (ru_RU-irina-medium, офлайн) + системные голоса устройства. На остальных таргетах группа не показывается вовсе — никаких задизейбленных фейков и «нейромоделей».
    • Цена 0 ₽, без джобы провайдера: офлайн-синтез сразу в WAV-файл (на десктопе/браузере файлового синтеза нет — поэтому и нет группы). Результат — обычный аудио-элемент канваса: плеер §3, редактор §4, очередь и журнал не нужны.
    • Скорость у Piper поддерживается (rate), высота — нет.

    Подсказки на карточках музыкальных моделей с lyrics: «Текст песни — в промпте, поле расширяется (§17)».

    15. Параметры TTS: голос и скорость

    • Чипы рендерятся только если ось есть у модели (исследование @pifiya §2): голос — у 15 из 19 TTS, скорость — только у 6 из 19. Нет оси — чип скрывается, а не дизейблится.
    • Алиасы осей (единого имени нет): голос = voice | gemini_voice | minimax_voice | qwen3_voice | voice_id; скорость = speed | speaking_rate | pace; язык = language | language_code (дальше — общие правила чипов §2).
    • Чип «Голос» → шит голоса: группа «Встроенные голоса» (голоса модели) и группа «Мой голос» (клонированные, §16) с меткой mic.svg. Если модель не принимает клонированный voice_id (принимают только voice-clone-tts — обязателен, elevenlabs-v4-tts и агрегатор tts — опционально), группа «Мой голос» у этой модели не показывается. mimo-v2-5-tts-voiceclone (0,01 ₽/1000 симв.) тоже требует клонированный Voice ID, но его происхождение провайдер публично не документирует (исследование §3.5) — в v1 модель скрыта из шита (не показывать то, что нечем заполнить). Условие возврата — появление у провайдера документации на загрузку голоса для Dune/MiMo, а не живая генерация: контракт создаёт голоса только под elevenlabs-движки, пикер клон-голосов для MiMo нечем заполнить структурно (доказательство — исследование @pifiya §3.3).
    • Чип «Скорость» → шит: пресеты 0.5× / 0.75× / 1× / 1.25× / 1.5× / 2× + слайдер; предпрослушивание без переписывания файла и A/B с оригиналом — паттерн аудиоредактора §4.
    • Прочие оси TTS (язык, формат) — по §2.

    16. Клонирование голоса «Мой голос»

    Контракт провайдера (исследование @pifiya §3, plusvibe.md стр. 126, движок только elevenlabs): POST /api/media/voices (создание, consent:true обязателен), GET /api/media/voices (список), DELETE /api/media/voices/{id} (удаление); сэмпл уходит audio_base64 (data:<mime>;base64,…) — публичного HTTPS у локальной записи нет.

    Вход: пункт «+ Мой голос» в шите голоса (§15). Шит создания:

    1. Образец: записать в приложении (mic.svg, 3–60 с) или импортировать wav/mp3 ≤ 10 МБ; после записи — плеер с прослушиванием (§3).
    2. Имя голоса.
    3. Уровень — с ценой до отправки (обязательно): «Обычный» — бесплатно (запись 3–60 с); «Premium» — 190 ₽ разово, максимальная похожесть (запись 10–60 с); «Голос ElevenLabs» — создание бесплатно, хранение 60 ₽/голос в месяц (первый месяц включён).
    4. Согласие: чекбокс «Подтверждаю, что это мой голос или у меня есть право его использовать» — кнопка «Создать голос» задизейблена, пока не отмечен. Это юридическое требование контракта, не формальность; обойти нельзя.

    Список «Мой голос» (GET /api/media/voices): имя, уровень, статус (готов / обрабатывается / ошибка), дата; действия — использовать (выбор в §15), удалить (подтверждение с именем). Добавление записей к существующему голосу (/samples) — v2, в v1 не показывать (простота); по живой доке добавление бесплатно и доступно только голосам уровня ElevenLabs — это ограничение учесть в v2.

    Лимиты и ошибки (карточки §8; сверено с живой докой провайдера): одна запись ≤ 10 МБ / ≤ 60 с / wav/mp3; на голос ≤ 25 записей суммарно ≤ 300 с и ≤ 50 МБ (достигаемо только при добавлении записей — v2); ≤ 20 добавлений в сутки на клиента. Клонированный voice_id дают voice-clone-tts (2,71 ₽/1000 симв., бонус — тайминги слов для субтитров §10), elevenlabs-v4-tts, агрегатор tts.

    17. Расширяемое поле промпта

    Поле дока уже многострочное (singleLine=false, maxLines 3) — расширение = раскрытие, а не замена контрола (факт кода, проверен).

    • Вход: кнопка раскрытия у поля — Icons.Filled.OpenInFull (extended уже в зависимостях, SVG не нужен); свернуть — Icons.Filled.FullscreenExit.
    • Раскрытая форма: стеклянный шит (§0) почти на весь экран; поле без ограничения maxLines; на компактных — во всю ширину, на широких — ограничено контейнером (M3 text-fields).
    • Переносы строк: в раскрытой форме Enter = новая строка (мультистрочная клавиатура); на десктопе зафиксировать явно: Enter — перенос, Ctrl+Enter — отправка.
    • Кнопка улучшения промпта (Icons.Filled.AutoFixHigh, справа у поля) наследуется в раскрытой форме и работает для длинных запросов и текстов песен; прогресс переписывания сохраняется. Кнопка «Создать» видна в форме — отправка не теряется.
    • Счётчик {введено}/{лимит модели} — обязателен: лимиты различаются в 50 раз (chatterbox-tts 300 → grok-tts 15000, исследование §5.2). Переполнение — счётчик в error, отправка задизейблена, текст не обрезается автоматически никогда.
    • Смена модели, когда текст длиннее нового лимита: предупреждение «Текст длиннее лимита выбранной модели» с действиями «Обрезать до лимита» (только явное действие) / «Оставить текст» — текст не теряется молча (§8, правило сохранённого ввода).
    • Черновики: раздельно на режим и флоу (§13), переживают сворачивание, переключение режимов/флоу и ошибки; хранение — MediaSettings/проект (§12), не remember.
    • Минимальный набор функций: раскрытие, переносы, счётчик, улучшение, отправка. Без разметки/превью/форматирования — простота прежде всего.

    19. Качество генерации изображений и параметры видео в тулбаре

    Добавлено директивой владельца: селектор качества генерации изображений (по умолчанию — низший уровень) и параметры видео (звук вкл/выкл, разрешение). Раздел дописан после §18 без сдвига якорей §0–§18. Факты и числа — по справке @pifiya /home/al/wiki/design/pots-quality-params-research.md (каталог от 2026-11-13: 208 моделей, живые price-table обеих моделей gpt-image-*); структурные факты (дефолты осей, подписи, priceRub) сверены по живому дампу каталога того же дня.

    19.1 Качество изображений — единственный селектор в тулбаре

    Один контрол на оба случая. Качество применяется и к генерации (текст→изображение), и к редактированию (изображение→изображение с референсами): второй точки выбора нет нигде — ни у референсов, ни в шите модели. Это корректно и по ценам: у gpt-image-2-6 генерация и редактирование стоят одинаково во всех 9 парах (разрешение×качество) прайс-таблицы (справка §3.1).

    Позиция и вид. Чип в тулбаре сразу после чипа разрешения: порядок «модель → соотношение сторон → разрешение → качество». Вид — существующий TopBarChip (как чип соотношения сторон): tertiaryContainer/onTertiaryContainer, labelMedium, скругление 12.dp, handCursor(); текст чипа — короткий русский лейбл текущего значения: «Низкое», «Базовое (2K)», «Минимальное». Других контролов качества в студии нет.

    Тап — выпадающий список, не шит: опций ≤ 4, список легче и быстрее. DropdownMenu с привязкой к чипу — паттерн уже живёт в тулбаре (выбор флоу §13). Пункт списка: лейбл уровня + вторая строка (цена — см. «Цена»; в режиме пометки второй строки нет); текущий выбор отмечен Icons.Filled.Check (уже используется в §13). Внизу меню — ценовая пометка, если она положена модели. Ховер-состояния обязательны (§0, десктоп).

    Видимость. Контрол показывается, только если у выбранной модели есть ось quality (select) с ≥ 2 опциями. Каталог 2026-11-13 — 7 таких моделей изображений (таблица ниже). У моделей без оси качества (gpt-image-2, nano-banana-pro и ещё 48) и с вырожденной осью из одной опции (grok-imagine-image-2.0) контрол скрыт, opts.quality не отправляется.

    Дефолт Low. По умолчанию — низший уровень модели: опция с минимальным priceRub, при равенстве или отсутствии цен — первая в порядке каталога. Правило перевешивает дефолт каталога и единое для всех осей качества (изображения и видео-flux-3, §19.2): серверный дефолт gpt-image-2-6 — high, и без селектора выбор 2K/4K молча тарифицировался бы по 17,33 ₽ вместо 6,77 ₽ — ровно эту ловушку стоимости закрывает директива. Повышение качества — всегда явное действие пользователя.

    Модель Уровни (значения оси) Дефолт приложения
    gpt-image-2-6 low / medium / high low — «Низкое» (дефолт каталога high переопределён)
    ideogram-4-5, ideogram-4-5-precise-edit very_low / low / medium / high very_low — «Минимальное»
    gpt-image-1-5 medium / high medium — низшего уровня у модели нет, честный минимум
    seedream-5 basic / high / ultra basic — «Базовое»
    seedream-4-5, seedream-5-uncensored basic / high basic

    Сохранение выбора. Выбор хранится по id модели в MediaSettings (паттерн хранения выбора §12/§13 — не remember); при смене модели восстанавливается сохранённое значение, если оно ещё есть в оси, иначе дефолт правила выше. Ошибкой выбор не очищается (§8, правило сохранённого ввода).

    Отправка. Выбранное значение всегда явно уходит в opts.quality async-запроса POST /api/media/generate — и в генерации, и в редактировании с референсами: неотправка равносильна выбору серверного дефолта каталога (у gpt-image-2-6 это high). Моделям без оси качества поле не добавляется: неизвестный параметр в strict-режиме — 422. Синхронный шорткат POST /v1/images/generations приложение сейчас не использует; если когда-либо будет — поле quality отправлять только моделям с осью качества в каталоге, иначе 400 по имени поля (справка §2).

    Лейблы уровней — на русском (§0, правило 5): low→«Низкое», medium→«Среднее», high→«Высокое», very_low→«Минимальное», basic→«Базовое», ultra→«Ультра», full→«Полное», draft→«Черновик»; суффикс в скобках каталожного лейбла сохраняется («Basic (2K)» → «Базовое (2K)», «Черновик (быстро и дёшево)» — уже русский, как есть); неизвестное значение — как в каталоге.

    Цена в выпадающем списке.

    1. Точная — только из строк прайс-таблицы (/api/media/price-table) по ключу (выбранное разрешение, качество, режим). У модели есть живая таблица — у каждого пункта вторая строка с ценой («6,77 ₽»); цены пересчитываются при смене чипа разрешения (паттерн пересчёта бейджа §2). В v1 таблица есть у gpt-image-2-6 (18 строк, все exact, генерация = редактирование):
    Разрешение Низкое Среднее Высокое
    1K 1,44 ₽ 1,44 ₽ 1,44 ₽
    2K и 4K 6,77 ₽ 12,19 ₽ 17,33 ₽

    На 1K все уровни одинаковы — это видно из самих цен, дополнительных пометок не нужно. priceRub опций оси для индикации цены не используется: у gpt-image-2-6 все три опции качества несут 1,44 ₽ — это цены «от» при дефолтном разрешении, а не цена уровня при выбранном разрешении (справка §3.1). 2. Ровная цена: прайс-таблицы нет, но все опции оси несут одинаковый точный priceRub — показывать его у каждого пункта + пометка «Качество не влияет на цену» (seedream-5: 3,72 ₽ на всех уровнях). 3. Иначе — без чисел, одна пометка внизу меню: «Среднее ≈ ×2, высокое ≈ ×3 к цене низкого уровня». Модели: ideogram-4-5, ideogram-4-5-precise-edit, gpt-image-1-5, seedream-4-5, seedream-5-uncensored, а также видео-flux-3 (§19.2). Пометка — консервативный ориентир сверху (измерено на gpt-image-2-6: реальные множители ×1,80 и ×2,56 на 2K/4K), а не обещание; точный итог всегда показывает котировка в доке перед отправкой (§2). Отдельные множители на пункт не рассчитываются и не показываются — точности каталожных данных для этого недостаточно.

    19.2 Видео-режим: звук и разрешение

    Тумблер «со звуком / без звука». Чип-переключатель только по осям с ключом audio | generate_audio (каталог 2026-11-13: 12 видео-моделей — kling-v2.6, kling-v3.0, kling-v3-omni, kling-v3-omni-reference, seedance-2.0, seedance-2.5, seedance-2-0-mini, pixverse-v6, pixverse-v6-max, wan-3-0-prime, flux-3, vidu-q4). Прочие звуковые оси (audio_url, keep_audio, keep_original_sound, audio_setting, save_audio, target_audio_url, source_audio_id) в этот тумблер не превращаются — семантика другая (входная дорожка, сохранение оригинала, аватары).

    Вид чипа: тот же TopBarChip с ведущей иконкой (18.dp, как иконки сегмента режимов). Включено — Icons.Filled.VolumeUp, фон primaryContainer/onPrimaryContainer (активный тумблер, паттерн §2); выключено — Icons.Filled.VolumeOff, фон tertiaryContainer (как неактивный параметр-чип). Текст — подпись оси из каталога как есть: «Со звуком» (kling-v2.6, kling-v3.0, vidu-q4), «Нативное аудио» (kling-v3-omni, kling-v3-omni-reference), «Генерировать звук» (seedance-2.0/2.5/2-0-mini, pixverse-v6(-max)), «Звук» (wan-3-0-prime), «Синхронный звук» (flux-3). Состояние читается по иконке и фону, подпись постоянна; contentDescription = «{подпись}: включено/выключено». Тап инвертирует значение; в запрос уходит opts["audio"|"generate_audio"] = true|false. Новые SVG не нужны — обе иконки в базовом наборе Icons.Filled.*.

    Дефолт — из каталога (default оси), не хардкодить: у 9 моделей «без звука» (false), у wan-3-0-prime, flux-3, vidu-q4 — «со звуком» (true). Дефолт отражает назначение модели (например, wan-3-0-prime — «говорящая»), поэтому к единому «выкл» не приводится — в отличие от качества, где дефолт всегда дешёвый (§19.1). Выбор живёт в params модели, как остальные чипы: при смене модели — сброс на дефолт каталога.

    Цена звука. На чипе чисел нет. Если опции оси несут priceRub, цена в бейдже дока пересчитывается при переключении (§2): kling-v2.6 35,64 → 71,28 ₽ (ровно ×2), kling-v3-omni ×1,43, kling-v3-omni-reference ×1,34, seedance-2.0 ×1,30, pixverse-v6 ×1,33, pixverse-v6-max ×1,36.

    Разрешение — по осям модели.

    • Ось resolution — существующий чип (69 из 88 видео-моделей), поведение не меняется.
    • Разрешение в оси quality: у pixverse-v6, pixverse-v6-max (360p/540p/720p/1080p) и runway-gen4 (720p/1080p) значения разрешения лежат в оси quality. Рисуется как чип разрешения (признак: все значения оси соответствуют \d{3,4}p или [24]k, регистр не важен), значение уходит в запрос под ключом quality. Без этого у трёх моделей контрола разрешения нет вовсе.
    • flux-3 (видео): ось quality = full/draft («Полное» / «Черновик (быстро и дёшево)», подписи каталога уже русские) — настоящее качество поверх оси resolution (720p/1080p). Рисуется контролом качества §19.1 (чип → выпадающий список), дефолт — дешёвый уровень draft (единое правило «дефолт Low»; дефолт каталога full переопределён), цены — режим пометки (прайс-таблицы у модели нет).
    • 14 моделей без осей разрешения/качества/длительности (в основном аватары/липсинк/апскейл: MiniMax-H3-Context-IR, p-video-edit, kling-ai-avatar, grok-imagine-extend, omnihuman-1-5, volcengine-lipsync, topaz-video-upscale, omnihuman-v2, lipsync-2-pro, sync-3, react-1, sync-3-avatar, ltx-2.5-audio-to-video, suno-music-video) — контролы не показываются: параметры задаются входом.

    Порядок чипов видео-режима: модель → разрешение (включая «разрешение в оси quality») → качество (flux-3) → длительность → звук. Максимум 4 чипа в ряду (§2), остальное — в шите параметров; у flux-3 ровно четыре (разрешение, качество, длительность, звук). Длительность — существующий чип (62 модели), без изменений.

    19.3 Общий механизм «ось → чип»

    Захардкоженный фильтр тулбара ["resolution", "duration"] заменяется обобщённым механизмом по образцу audioToolbarParams() (§2) — одно изменение закрывает качество изображений (19.1), тумблеры звука и разрешение трёх видео-моделей (19.2):

    • приоритетный порядок осей: resolution → quality → duration → audio/generate_audio;
    • технический стоп-лист (никогда не становится чипом): входные и служебные оси — seed, negative_prompt, guidance_scale, *_url/*_id-поля и прочие по стоп-листу §2;
    • не больше 4 чипов в ряду, переполнение — в шите параметров (MediaParamSheet);
    • вид чипа по типу оси: select с короткими значениями — чип со списком (качество — выпадающий список §19.1, остальные оси — существующий шит), toggle — чип-переключатель §19.2.

    Существующие чипы (разрешение, длительность, соотношение сторон) и аудио-флоу не ломаются: механизм расширяет фильтр и добавляет типы чипов, а не заменяет существующий рендер.

    19.4 Ошибки и края — паттерн §8

    • Сервер отклонил качество (неизвестный параметр или сочетание, 422/400) → существующая строка «Параметры не подходят»; спасение «Сбросить параметры» возвращает качеству дефолтный низший уровень; промпт и референсы сохранены (§8, правило сохранённого ввода).
    • Прайс-таблица недоступна (сеть) → список открывается без ценовых строк, в режиме пометки; выбор не блокируется.
    • Сохранённое значение исчезло из оси (каталог обновился) → тихий откат на дефолт правила, без ошибки.
