Макеты и спецификация к карточке `t_b31b2265`. Всё, что здесь описано, относится к
`composeApp/src/commonMain/kotlin/com/pusios/pots/ui/settings/` — сам код приложения не менялся.

## 1. Карточка модели (`ModelSelectionSheet.kt`, `ModelCard`)

### 1.1 Геометрия на 360 dp

| Элемент | Значение |
|---|---|
| Сетка листа | `LazyVerticalGrid(GridCells.Adaptive(300.dp))`, `contentPadding 8`, зазор 8 |
| Карточка | 344 dp по ширине (342 с рамкой), радиус 12, padding 16, рамка 1 dp `rgba(255,255,255,.08)` |
| Контент карточки | 308 dp |
| Ряд плиток | 6 равных плиток по 46.3 dp + 5 зазоров по 6 dp = 308 dp |
| Плитка | высота 60 dp, радиус 10, padding 0 / 2 |
| Внутри плитки | иконка 13 dp, зазор 3 dp, значение 14/16 |
| Отступы по вертикали | 16 (сверху) · заголовок 24 · 6 · мета 16 · 10 · плитки 60 · 16 (снизу) = **148 dp** |
| Выбранная карточка | та же высота, меняется только цвет и появляется галочка 20 dp |

Плитки не кликабельны — правило «touch target ≥ 44 dp» к ним не применяется. Минимальная
ширина 44 dp соблюдается косвенно: 46 dp получается расчётом, а при сужении экрана
пересчитывается от доступной ширины (см. 1.5).

### 1.2 Содержимое строк

1. **Название** — `titleMedium`, одна строка, `TextOverflow.Ellipsis`, `weight(1f)`.
2. **Бейдж «Free»** — `isFreeTier`, `labelSmall` 11/14, 600, padding 2 / 6, радиус 4.
3. **Галочка выбора** — 20 dp, залитый круг с вырезом (`#D9B8FF`), только в выбранном
   состоянии. Круг, а не простая галочка: в плитке Vision стоит обычная галочка, и две
   одинаковые «птички» в одной карточке читались бы как одно и то же.
4. **Мета-строка** — `bodySmall` 12/16, `onSurfaceVariant`: `дата · параметры`
   (`formatReleaseDate` + `parameterCount`). Контекст из меты **уходит** — он теперь в плитке.
   Если ни даты, ни параметров нет — показываем `id` приглушённым (пример «локальная модель»).
5. **Ряд плиток** — 6 плиток, порядок фиксирован.

### 1.3 Плитки: порядок, иконки, значения

| # | Плитка | Иконка | Значение | Поле `SettingsModel` | Нет данных |
|---|---|---|---|---|---|
| 1 | Цена входа | `↓` (`ic_price_input`) | число + «M» | `pricePerMillion` | контур + «—» |
| 2 | Цена выхода | `↑` (`ic_price_output`) | число + «M» | `outputPricePerMillion` | контур + «—» |
| 3 | Контекст | уголки (crop_free) | `200K` / `1M` | `contextWindow` → `formatContextWindow` | контур + «—» |
| 4 | Оценка | звезда | `1455` | `arenaScore` | контур + «—» |
| 5 | Tools | гаечный ключ | количество или `✓` | появится после карты исследователя | контур + «—» |
| 6 | Vision | глаз | `✓` / `—` | появится после карты исследователя | контур + «—» |

Решения и обоснования:

- **«M» = за миллион токенов.** Цена — USD за 1 млн, символ `$` не добавляем: он съедает
  ~6 dp в двух плитках, а смысл уже задан «M». Формат числа — существующий
  `formatPricePerMillion` (обрезает лишние нули: `3.0 → 3`, `0.28 → 0.28`).
- **Кэш (`cachePricePerMillion`) в ряд не входит.** Семь плиток на 360 dp дают 40 dp на
  каждую — «163K» перестаёт влезать. Кэш — производная от цены входа; если понадобится,
  он идёт третьей строкой в раскрытой карточке, а не в этом ряду.
- **Tools числом, если бэкенд отдаёт список** («11»); если пришёл только флаг — `✓`.
  Слот и высота не меняются, поэтому разнобой данных ряд не ломает.
- **Vision бинарна**: `✓` или «—». Для «—» плитка тоже считается пустой (контур без заливки).

### 1.4 Состояния плитки

| Состояние | Заливка | Контур | Иконка | Значение |
|---|---|---|---|---|
| есть данные | `rgba(255,255,255,.07)` | `rgba(255,255,255,.09)` | `#A29BB0` | `#F2F0F6` |
| нет данных | нет | `rgba(255,255,255,.16)` | `#5C5768` | `#6E6879`, текст «—» |
| в выбранной карточке | `rgba(255,255,255,.09)` | `rgba(234,221,255,.16)` | `rgba(234,221,255,.62)` | `#FBF7FF` |
| пустая в выбранной | нет | `rgba(234,221,255,.22)` | `rgba(234,221,255,.35)` | `rgba(234,221,255,.42)` |

Пустая плитка **не исчезает**: место сохраняется, ряд не «прыгает» при прокрутке списка
и при сравнении соседних карточек. Это главное требование к состоянию «нет данных».

### 1.5 Поведение на разных ширинах

- **360 dp (телефон):** как в макете, 46 dp на плитку.
- **320 dp:** карточка 304 dp, контент 268 dp, плитка 40 dp → значение 14/16 ещё влезает
  (`0.28M` ≈ 36 dp), иконка остаётся 13 dp. Если ширина меньше 300 dp — значение
  уменьшается до 13/16, иконка до 12 dp (единственное место, где допустим меньший кегль).
- **Планшет (≥ 600 dp):** сетка даёт 2 колонки по ~292 dp — плитки те же 46 dp.
  Если карточка окажется шире 400 dp, плитка ограничивается `widthIn(max = 72.dp)`,
  ряд выравнивается по левому краю, свободное место остаётся справа (не растягиваем
  плитки до бесконечности — значения «плывут» по центру и ряд теряет ритм).

### 1.6 Что менять в коде

Внутри `ModelCard` вместо `detailText` + `PriceChip` — `Row` из шести плиток. Набросок:

```kotlin
Row(
    modifier = Modifier.fillMaxWidth().padding(top = 10.dp),
    horizontalArrangement = Arrangement.spacedBy(6.dp),
) {
    Tile(Icons.Filled.ArrowDownward, priceText(model.pricePerMillion), unit = "M")
    Tile(Icons.Filled.ArrowUpward, priceText(model.outputPricePerMillion), unit = "M")
    Tile(Icons.Outlined.CropFree, model.contextWindow?.let(::formatContextWindow))
    Tile(Icons.Filled.Star, model.arenaScore?.toString())
    Tile(Icons.Filled.Build, model.toolsCount?.toString() ?: model.hasTools?.let { if (it) "✓" else null })
    Tile(Icons.Filled.Visibility, model.supportsVision?.let { if (it) "✓" else null })
}
```

`Tile(icon, value, unit)` — `Modifier.weight(1f).height(60.dp)`, `RoundedCornerShape(10.dp)`,
заливка/контур по таблице 1.4, `value == null` → вариант «нет данных» (без заливки, «—»).
`PriceChip` и `detailText` после этого не нужны; `arenaScoreColor` переносится на цвет
значения плитки «Оценка» (порог тот же: ≥1400 / 1350 / 1300 / 1250).

## 2. Ряд сортировки (`ModelSelectionSheet.kt:174-195`)

### 2.1 Проблема

Шесть `FilterChip` с подписями занимают **542 dp** при доступных **344 dp** в `Row` без
скролла: «Рекомендуемые» и «Бесплатно» уезжают за край. Замеры подписей: Дата 57, Оценка 75,
Контекст 83, Цена 60, Рекомендуемые 132, Бесплатно 95 (+ 5 зазоров по 8).

### 2.2 Решение: только иконки

| Элемент | Значение |
|---|---|
| Ряд | `Row`, padding 6 сверху/снизу, 8 по бокам, зазор 8 (6 при узком экране) |
| Кнопка | 44 × 44 dp минимум, `weight(1f)` до 56 dp, радиус 12 |
| Иконка | 20 dp, `currentColor` |
| Каретка направления | 12 dp, `right 3`, `bottom 2`, только у активной сортировки |
| Разделитель | 1 × 24 dp, `rgba(255,255,255,.09)`, между сортировкой и фильтром |
| Итог на 360 dp | 6 × 46 + 6 × 8 + 1 = 325 dp ≤ 344 dp (запас 19 dp) |

| Кнопка | Иконка | Тап | Повторный тап |
|---|---|---|---|
| Дата | календарь | `ModelSortOption.Date` | новые ↔ старые |
| Оценка (по умолчанию) | звезда | `Score` | выше ↔ ниже |
| Контекст | уголки | `Ctx` | больше ↔ меньше |
| Цена | `$` | `Price` | дороже ↔ дешевле |
| Рекомендуемые | палец вверх | `Recommended` | направление не меняется |
| Бесплатно | ярлык | фильтр `isFreeTier` | выкл/вкл |

Направление по умолчанию = порядок `comparator` в `ModelSortOption` (для цены — возрастание,
для остальных — убывание); каретка показывает **фактическое** направление, а не зашитое «вниз».
У «Рекомендуемых» каретки нет: составной ключ не имеет осмысленного обратного порядка.

### 2.3 Состояния кнопки

| Состояние | Заливка | Контур | Иконка |
|---|---|---|---|
| неактивна | прозрачная | `rgba(255,255,255,.08)` | `#9C96A8` |
| активна | `rgba(187,134,252,.16)` | `rgba(187,134,252,.50)` | `#D9B8FF` |
| нажата | `rgba(255,255,255,.07)` | `rgba(255,255,255,.12)` | как в предыдущем |
| фильтр включён | `rgba(110,231,160,.12)` | `rgba(110,231,160,.45)` | `#6EE7A0` |

Фильтр визуально отличается от сортировки (зелёный + разделитель): это не «ещё один вариант
сортировки», а переключатель.

### 2.4 Подпись по долгому нажатию

400 мс удержания → подсказка над кнопкой: «Контекст · по убыванию». Позиция — по центру
кнопки, 6 dp над ней, гаснет через 2 с после отпускания. Текст = подпись из ресурса +
текущее направление (для фильтра — просто «Только бесплатные»).

### 2.5 Нехватка места

| Ширина экрана | Поведение |
|---|---|
| ≥ 336 dp | зазор 8, кнопки тянутся `weight(1f)`, максимум 56 dp |
| 320…335 dp | зазор 6, кнопки ровно 44 dp (6 × 44 + 5 × 6 = 294 ≤ 304) |
| < 320 dp | `LazyRow`, зазор 6, кнопки 44 dp, справа затухание 16 dp; последняя кнопка видна частично — это подсказка о прокрутке |
| планшет ≥ 600 dp | кнопка растёт до 56 dp и останавливается, подписи **не появляются** (поведение одинаково на всех экранах) |

Кнопка никогда не становится уже 44 dp — вместо сжатия включается прокрутка.

### 2.6 Доступность

- `contentDescription` у каждой кнопки: подпись + направление («Сортировать по оценке,
  по убыванию»). Иконка без текста иначе нема для TalkBack.
- Активная сортировка: `Modifier.semantics { selected = true }`.
- Фильтр: `Modifier.toggleable(role = Role.Switch)` — не `selectable`.
- Ряд — один `Row`/`LazyRow` без заголовка; перед ним озвучивается «Сортировка».

## 3. Шапки секций (`MediaModelsSettings.kt:100`)

### 3.1 Баг

```kotlin
Text(title, style = MaterialTheme.typography.labelLarge, modifier = Modifier.padding(top = 12.dp))
```

`labelLarge` задаёт только размер/вес и **не задаёт цвет** — текст наследует `LocalContentColor`,
а в тёмной теме он чёрный. Итог: `#000000` на `#121212` = **1.12 : 1** (норма AA — 4.5 : 1).
В светлой теме тот же код даёт 18.6 : 1, поэтому дефект не был заметен.

### 3.2 Как надо

| Элемент | Значение |
|---|---|
| Контейнер | `Row(verticalAlignment = Alignment.CenterVertically)` |
| Отступы | top 12, start/end 8, bottom 8 |
| Иконка | 18 dp, `tint = MaterialTheme.colorScheme.primary`, `contentDescription = null` |
| Зазор иконка → текст | 8 dp |
| Заголовок | `titleSmall` 14/20, вес 600, `letterSpacing 0.1`, **`color = colorScheme.onSurface`** |
| Счётчик | `labelSmall` 11/16, `onSurfaceVariant`, `Modifier.padding(start = 8.dp)` |
| Строка | одна, `maxLines = 1`, `TextOverflow.Ellipsis` |

Контраст: `#FFFFFF` на `#121212` = **18.7 : 1**, `#B7B1C4` (счётчик) = **9.0 : 1**,
`#BB86FC` (иконка) = **7.1 : 1**.

```kotlin
Row(
    modifier = Modifier.fillMaxWidth().padding(top = 12.dp, start = 8.dp, end = 8.dp, bottom = 8.dp),
    verticalAlignment = Alignment.CenterVertically,
    horizontalArrangement = Arrangement.spacedBy(8.dp),
) {
    Icon(icon, contentDescription = null, tint = colorScheme.primary,
         modifier = Modifier.size(18.dp))
    Text(
        text = title,
        style = MaterialTheme.typography.titleSmall,
        color = colorScheme.onSurface,
        maxLines = 1,
        overflow = TextOverflow.Ellipsis,
        modifier = Modifier.weight(1f),
    )
    count?.let {
        Text("$it", style = MaterialTheme.typography.labelSmall,
             color = colorScheme.onSurfaceVariant)
    }
}
```

### 3.3 Иконки и данные

- «Изображения» — `Icons.Outlined.Image`, «Видео» — `Icons.Outlined.Movie`,
  «Аудио» — `Icons.Outlined.GraphicEq`. Своя библиотека `ui/icons/PotsIcons.kt` содержит
  клубные иконки (`ClubKey`, `ClubCloud`, `LocalModel`, `PotsGame`) и к медиа не относится.
- Секция «Аудио» добавляется новой `ModelPicker(title = "Аудио", kind = MediaKind.Audio)`;
  подписи выносятся в ресурсы (`media_section_images/_video/_audio`) вместо литералов.
- Счётчик — количество моделей в секции; если каталог ещё грузится, счётчик не показываем
  и место под него не резервируем (названия секций короткие, обрезки не будет).

Бюджет ширины при 360 dp: 360 − 16 (поля панели) − 24 (padding строки) − 62 (цены) −

высота строки не меняется. Полный ID доступен по долгому нажатию (подсказка снизу строки,
гаснет через 2 с) и через `contentDescription` для TalkBack.

|---|---|
| Тап вне панели | закрыть без изменения выбора |
| Выбор строки | закрыть панель, показать выбор в поле, очистить поиск |
| Esc / «назад» | сначала закрывает панель, второе нажатие — лист/экран |
| Клавиатура | поле поиска поднято над клавиатурой, панель сжимается до 3 строк |
| Нет цен (локальная модель) | в обеих ячейках «—» приглушённым, в подписи строки — «локальная» |
| Каталог грузится | панель не открывается, в поле «Загрузка моделей…», скелетон строк |
| Ошибка загрузки | одна строка: «Не удалось загрузить список» + «Повторить» |

### 4.6 Не дублировать поиск

Если лист уже содержит `PotsSearchField` (появляется при > 6 моделях), выпадающий список
собственный поиск не добавляет — иначе на экране два поля ввода с одинаковым поведением.

## 5. Общие правила

- **Иконки** — inline SVG / `ImageVector` с `currentColor`, размеры 13 / 18 / 20 dp по
  контексту. Никаких эмодзи.
- **Числа** — `tabular-nums`, чтобы колонки цен и значений не дрожали при прокрутке.
- **Пусто ≠ ноль.** Отсутствие данных показываем «—» и приглушённым контуром, а не `0`
  и не пустым местом: место в макете сохраняется всегда.
- **Одна нотация цен** во всех местах: `↓` вход, `↑` выход, «M» = за миллион.
- **Тема.** Все цвета — из `MaterialTheme.colorScheme`; в макетах тёмная тема. При
  OLED-фоне (`isOledFlavor`) карточка становится прозрачной с рамкой `outlineVariant` —
  это уже реализовано в `potsAdaptiveCardSurface`, плитки от этого не меняются.

## 6. Что осталось открытым

- Поля `tools` и модальностей появятся после карты исследователя — плитки 5 и 6 заложены
  заранее, тип значения (количество или флаг) на вёрстку не влияет.
- Порог «широкой» карточки на планшете (400 dp) — оценка; проверить на реальном
  `GridCells.Adaptive(300.dp)` после сборки.
- Цвета оценки (`arenaScoreColor`) в макетах не показаны: сейчас это тёмно-зелёный
  `#2E7D32`, который на `#121212` даёт 3.2 : 1. Если оставляем цвет — нужно осветлить
  до `#6EE7A0` / `#F9A825` (порог ≥ 4.5 : 1). Решение за владельцем.

## 7. Проверка

Макеты открыты в браузере (Chromium, 1400 px), снята полная страница, состояния просмотрены
по отдельности: пустые плитки, выбранная карточка, все состояния кнопок, обрезка на 300 dp,
«ничего не найдено», длинное имя в строке и в поле. Геометрия проверена `getBoundingClientRect`:
